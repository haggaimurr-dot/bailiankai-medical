# 百莲凯微信小程序 · M1 预约、M2 方案/照片与 M3 随访演示

面诊照片页提供正面与左右 45° 指引、独立相机/相册入口。照片先在本机检查尺寸、清晰度与光线，再预览并核对清晰度和角度；完成两项确认才上传。角度尚未自动校准，需人工核对本人左右方向，能力不可用时明确提示。运行 `pnpm --filter @bailiankai/miniprogram test:photos` 执行39项专项回归；`smoke:care --photos-only --screenshots` 使用选择器替身和几何图片验证真实上传下载，截图保存在根目录 `tmp/photo-*.png`。未替代原生选择器或真机验收；流程与交互脚本见 [面诊照片拍摄与验收](../../docs/面诊照片拍摄与验收.md)。

微信原生 TypeScript / WXML / WXSS，基础控件来自 TDesign MiniProgram。包含独立首页、医生介绍、排班查询、预约表单、我的预约、预约详情、照片资料、治疗方案和随访页面。数据通过 Go API 从数据库读取；院区、医生、患者、照片与方案均只能使用开发演示资料。

默认启动页为 `pages/home/index`，展示品牌、面诊到随访流程、面诊准备和当前院区的前两位医生。首页支持切换院区、下拉刷新与失败重试；团队接口失败时，流程及功能入口仍可使用。预约入口进入所选院区的排班，未取得院区时先进入医生列表；“我的预约”和“治疗档案”进入已有患者功能。首页不创建患者身份、不申请照片授权。

首页医生卡片和医生列表可进入 `pages/doctor-detail/index`，读取所选医生的简介、专业方向及出诊院区，展示院区通用服务流程和面诊准备说明。详情底部预约按钮进入该医生的未来 7 天排班，再选择时段填写预约；缺失、失效或院区不匹配的医生资料会提示重新选择，支持下拉刷新和重试。

## 排班预约扩展（2026-10-07）

已满时段可登记候补，候补不占名额；在预约详情主动查询空位并申请转为待确认，再由工作人员审核。待确认或已确认预约可在同医生同院区内原子改期，成功后重新待确认；结果不明时保留原申请重试。预约详情新增服务端状态时间线。需迁移29，执行 `test:booking-rules` 和构建；规则、测试结果及原生待验收项见 [小程序排班预约扩展与验收](../../docs/小程序排班预约扩展与验收.md)。

## 启动

1. 在仓库根目录执行 `pnpm install`，按根目录 README 启动数据库和 API。
2. 在根目录执行 `pnpm --filter @bailiankai/miniprogram build`，检查类型并将 `.ts` 编译成同目录 `.js`。生成文件已忽略，不提交。开发时另开终端运行 `pnpm --filter @bailiankai/miniprogram watch`，修改后自动重新生成；监听模式不执行类型检查。
3. 在微信开发者工具中导入本目录 `apps/miniprogram`。项目配置了机构 AppID，小程序目录已配置为 `app/`。
4. 在开发者工具菜单执行 **工具 → 构建 npm**。项目已通过 `packNpmRelationList` 将本目录 `package.json` 中的小程序依赖构建到 `app/miniprogram_npm/`；该目录不提交。
5. 点击编译。开发者工具读取上一步生成的 JavaScript。项目关闭了 IDE 内置 TypeScript 编译插件，避免不同工具版本造成重复编译或漏编译。

项目必须保持 `setting.es6=true`（开发者工具“将 JS 编译成 ES5”）。本地脚本将业务 TypeScript 转为 CommonJS，但 TDesign npm 组件仍含 `import/export`，需要开发者工具进一步转译。关闭该选项会触发 `Unexpected token 'export'`、`Cannot use import statement outside a module` 和组件模块未定义。修改此设置后清除编译缓存再重新编译。

API 地址在 `app/config/api.ts`，默认 `http://127.0.0.1:8080/api/v1`。本地开发关闭了合法域名校验。患者登录模式默认 `wechat`，服务端需配置 `WECHAT_APP_ID` 与 `WECHAT_APP_SECRET`。虚构患者联调可显式将 `PATIENT_LOGIN_MODE` 改为 `demo` 并构建。首页“我的资料”提供姓名查询修改、独立账号手机号授权/更新/撤回和退出当前设备；账号手机号不改写预约联系人。详见 [患者身份与资料](../../docs/患者身份与资料.md)。

在“我的预约”打开一条待确认或已确认预约的详情，可进入照片资料或治疗方案。照片上传前需要单独同意诊疗用途；支持撤回授权和按角度重传。请勿上传真实照片。方案页仅展示演示医护发布的版本，不显示后台草稿。

当前 API 仅监听电脑 loopback，修改成局域网 IP 仍无法供手机访问。真机验证需要先提供受控测试服务 / HTTPS 测试域名，再设置 API 地址及微信 request 合法域名。微信登录代码已接入，实际凭据、手机号接口权限、隐私指引及真机流程尚需验收。

## 验证

在仓库根目录执行 `pnpm --filter @bailiankai/miniprogram typecheck`。共享 API 类型由 `packages/contracts/openapi.yaml` 生成，小程序使用 `import type` 引用，不会将根目录文件作为运行时代码打包。

身份与恢复记录的并发回归执行 `pnpm --filter @bailiankai/miniprogram test:session`，无需连接微信工具。它加载实际服务模块，验证并发重建身份、旧请求迟到、随机编号生成期间切换身份等情况。

医生详情回归执行 `pnpm --filter @bailiankai/miniprogram test:doctor-detail`，加载实际页面与服务模块，模拟微信平台边界，验证首页/列表入口、资料读取、错误重试、卸载后的迟到响应，以及详情到排班再到预约的医生与院区传递；此检查已纳入根目录 `pnpm check`。

### 模拟器自动化联调

需要 Node 22+、本地 API 正常运行，以及微信开发者工具已开启服务端口。以下命令在仓库根目录执行，CLI 路径按本机安装位置调整：

```powershell
pnpm --filter @bailiankai/miniprogram build
& 'D:\app\wechatdev\微信web开发者工具\cli.bat' auto --project 'D:\proj\百莲凯医疗美容\apps\miniprogram' --auto-port 9420 --trust-project
pnpm --filter @bailiankai/miniprogram smoke
pnpm --filter @bailiankai/miniprogram smoke:booking
```

`smoke` 通过原生模拟器检查医生和未来日期排班的页面数据、渲染数量与实际 API 是否一致。它不会上传小程序或生成预览码。

验证后台更新同步时，执行 `pnpm --filter @bailiankai/miniprogram smoke --write-check`。脚本读取根目录 `.env` 的本地演示令牌，临时切换最后一位医生后天第一个时段的开诊状态，触发页面下拉刷新并核对版本，然后恢复原容量和状态。数据库版本号会正常递增；请只对本地演示库运行。

`smoke:booking` 使用隔离的演示身份，验证原生表单提交、后台确认、详情刷新、取消与列表状态，以及“服务端已创建、客户端未收到成功响应”时的原申请恢复。脚本同时核对页面数据与实际渲染节点；结束会取消本次创建的有效预约、恢复原来的三个业务缓存项，保留数据库审计记录。请与后台其他写入测试错开运行，避免同时占用同一号源。

开发者工具检查：

- 医生列表加载、院区切换、医生的“查看排班”入口。
- 首页医生卡片和列表的详情入口，详情资料/服务流程/面诊说明展示，底部预约按钮预选正确医生，点击只进入一个页面。
- 全部医生 / 单个医生和未来 7 天日期筛选，快速切换不会显示旧请求结果。
- 可用、已满、停诊、空列表、网络错误、重试及下拉刷新。
- 更新数据库排班后下拉刷新，小程序与后台显示同一份数据。
- 从可用时段进入预约表单，使用默认“演示访客 / 13800000000”或其他明确的演示资料。
- 提交后查看待确认状态、确认截止时间；工作人员确认或拒绝后刷新结果，拒绝时显示原因。
- 时段开始前取消待确认或已确认预约，取消前出现确认对话框；版本冲突先刷新，不覆盖后台新状态。
- “我的预约”按状态筛选、分页及刷新；网络异常时查询原申请结果或使用同一编号重试。

日期和时段按北京时间显示。日期在每次刷新时更新；服务端仅返回尚未开始的时段。

## 身份与提交恢复

- 首次进入预约功能时，服务端生成设备独立的随机演示会话，本地仅保存该会话。请求不接受任意患者编号作为身份凭据。
- 会话过期或收到 401 后会清除旧令牌并提示过期。只有用户确认后才创建新身份；新身份不会继承旧身份的预约。多个页面共享同一次重建操作。
- 提交前，先在本地保存随机申请编号、原始提交资料和所属演示身份。网络超时或服务异常时保留恢复记录；重试复用原编号和原资料。
- 按申请编号查询返回 404 时，原请求仍可能正在执行，页面不会换编号重复创建。明确的已满、停诊等业务拒绝才结束该次申请；幂等冲突继续保留原申请用于查询。
- 再次读取恢复记录时，会清除已保存超过 24 小时的联系资料，继续保留申请编号用于查询结果。不会因为本地资料过期而自动丢弃在途申请；放弃恢复需用户明确确认。

样式 token 来源为现有设计资源包，通过根目录 `tokens:sync` 同步到 `app/styles/mlk.mobile.wxss`。

## M3 随访

恢复日历入口位于首页和治疗档案，复用 `/me/followups` 的当前身份随访数据，读取全部分页后按北京时间归日。月历支持切换月份、回到今天和日期选择，计划日期展示随访任务及待填写状态，提交日期展示反馈，回评日期展示医护回评和异常处理。全部日期的待填写任务集中列出，逾期仍可进入原随访表单；日历详情链接使用 `taskId` 选中对应任务。返回日历和下拉刷新会重新读取状态，分页失败显示重试，不展示不完整日历。

执行 `pnpm --filter @bailiankai/miniprogram test:recovery-calendar` 验证北京时间跨日、闰月/跨年、分页读取、对应任务链接、提交后刷新、分页失败重试及过期/卸载保护。该检查已纳入根目录 `pnpm check`。原生月历渲染和真机操作仍需微信开发者工具验收。

后台 `/followups` 记录实际治疗，关联已发布方案并生成任务。预约状态变为“已治疗”；患者从“我的预约 → 我的随访任务”或预约详情进入，提交症状、感受和本次随访照片，刷新查看医护回评或异常处理记录。

医护更正治疗记录后，患者在同一随访页可查看当前版本与原始、更正历史。治疗时间如有合法更正，尚未开始的任务计划时间随之更新。

照片为选填。诊疗及随访用途授权版本为 `photo-care-v2`，旧 v1 授权需重新同意；撤回同时覆盖本次预约的面诊和随访照片。每个任务有独立照片，反馈提交后不能再替换，已治疗预约的面诊照片也仅供查看。

```powershell
pnpm --filter @bailiankai/miniprogram smoke:care --photos-only
pnpm --filter @bailiankai/miniprogram smoke:care --plan-only
pnpm --filter @bailiankai/miniprogram smoke:followup
```

M2 照片与方案已分场景通过原生模拟器验收；连续跨页仍有已记录的自动化导航超时，可重开工具后运行对应场景。M3 单页内完整流程已通过原生模拟器，覆盖任务与图片实际渲染、上传、普通回评、异常处理、撤回授权与旧任务照片保留。系统图片选择器和确认框使用测试替身，上传/下载和服务端读写是真实调用。未验收真实系统图库/相机选择及真机。尚未接入微信订阅消息，任务到期在页面显示，不自动发送通知。
