# 双端在线咨询与客服工作台

小程序首页进入“在线咨询”，登录后选择院区、咨询类型，填写标题和问题；提交会建立咨询工单。患者可分页查看本人服务记录、客服回复和工单状态，补充问题。后台 `/support` 为独立客服工作台，主管及客服角色可进入，沿用员工账号、停用校验与院区权限。

## 工单与分派

- 工单状态：待分派、处理中、待客户回复、已解决、已关闭。已解决工单收到患者新消息会恢复处理中；关闭后保留记录，新的问题须新建工单。
- 客服仅能查看所属院区的待分派工单和自己负责的工单。可主动接手未分派工单，默认24小时内跟进；接手后才能回复、记录内部服务和设置跟进期限。
- 主管可查看其有权院区全部工单，分派或改派到同院区在岗的客服 / 主管。分派须填写原因及未来跟进期限。账号停用不会自动改派历史工单，主管应在工作台完成交接。
- 工作台支持状态、我的工单、待分派和逾期未解决筛选；后台队列及当前详情每3秒自动同步；小程序前台打开最新消息页时每3秒同步，切到后台停止同步。编辑中的正文与附件保留，后台有新记录提示；查看较早记录时可返回最新消息。
- 内部服务记录、分派原因、状态操作原因和实际跟进记录保留操作账号及时间，患者接口不返回这些内部事件。跟进期限采用北京时间，未解决且超过期限的工单标记逾期。

## 接口与数据

数据库迁移：`00045_support.sql`，执行现有迁移并重启 API。新增 `support_tickets` 与 `support_events`；增强功能迁移 `00071_support_enhancements.sql` 增加评分字段及 `support_attachments`。这些数据均独立于医疗问诊记录；不将客服留言作为诊疗问诊或医嘱。

患者：`GET/POST /api/v1/me/support`、`GET /api/v1/me/support/{ticketId}`、`POST /api/v1/me/support/{ticketId}/actions`（message 或 rate）。提交咨询及消息沿用当前隐私说明授权。

员工：`GET /api/v1/admin/support`、`GET /api/v1/admin/support/agents`、`GET /api/v1/admin/support/{ticketId}`、`POST /api/v1/admin/support/{ticketId}/actions`。操作包括 message、note、assign、auto_assign、status、followup。列表和详情事件均分页，每页最多100条。

标题最多100字，正文 / 操作记录最多2000字。写操作必须带16–80位 `requestKey`；变更带当前 `version`。事务内锁定工单，拒绝并发覆盖；同一操作原请求重试不会重复写入，同键不同内容返回409。双端保留结果不明的请求，可原样重试；版本冲突须刷新记录、核对后重新编辑。

## 自动分派、附件与评分

新咨询创建时自动选择所属院区在岗的客服，按其未完成工单数由少到多分派，数量相同时按账号编号排序；主管不参与自动候选。默认24小时内跟进，同时写入内部系统分派记录。院区锁和读已提交事务使同院区并发创建使用最新工作量。暂无合适人员时保留待分派，主管可使用“自动分派”重试，也可按原流程手动分派；已有负责人不被自动覆盖。

后台及小程序可在工单消息中附加 JPG、PNG、PDF；后台内部服务记录也可附加附件。每条消息最多3个，每个2MB，可单独发送附件。`attachments` 为 `{name,data}` 数组，`data` 是 Base64 内容；服务端检查实际文件类型、名称、数量与大小。附件与消息在同一事务保存，随原请求重试不会重复落库。文件字节存入私有数据库，不生成公开地址；备份数据库时须包含附件表。

双端通过 `GET /api/v1/{admin|me}/support/{ticketId}/attachments/{attachmentId}` 携带各自会话令牌下载，校验工单、院区、负责人及消息可见权限；客户不能读取内部记录的附件。详情仅返回附件编号、名称、类型与大小。后台附件待重试请求存入 IndexedDB，小程序存入私有本地文件，避免大附件超出单项键值存储容量。

工单已解决或已关闭后，客户可提交1–5星及最多500字评价，每张工单仅评价一次。`rate` 操作带 `rating`、`content`、`version`、`requestKey`；未填写评价文字时界面提交“服务评分”。客服不能代客户评分。评分显示在后台详情和客户服务记录，关闭工单仍允许评分；同键重试保留一次结果。

消息采用前台3秒轮询，连接失败自动重试；未接入 WebSocket、微信原生客服或离线推送。小程序真机附件选择、PDF打开及前后台切换仍需验收。

`pnpm exec playwright test tests/support.spec.ts` 验证客服工作台接手、回复、内部记录、北京时间期限、自动分派、附件跨刷新恢复、评分展示及新消息同步时的草稿保留。浏览器测试使用接口模拟；真实事务及权限由 MySQL 集成测试覆盖。微信开发者工具及真机交互尚需验收。

## 验证

`pnpm --filter @bailiankai/miniprogram test:support` 验证北京时间、身份切换、迟到响应隔离、结果不明时原请求重试及带版本的回复。

在项目环境加载 `TEST_DB_DSN` 后运行 `go test ./internal/httpapi ./internal/store -run Support -count=1`，验证角色和输入限制、并发创建去重、患者 / 客服隔离、内部记录过滤、状态转换、关闭限制、并发自动分派、附件下载隔离、附件重试去重和结单评分；数据库测试仅使用 `_test` 独立库。再执行契约检查、双端类型检查与构建。
