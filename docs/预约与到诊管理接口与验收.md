# 后台预约与到诊管理

入口：后台「预约管理」和「到诊工作台」(`/arrivals`)；患者小程序「我的预约 → 预约详情 → 到院扫码签到」。

## 权限与审批

审批按钮使用登录会话返回的能力列表，接口返回的 `canReview` 同时校验预约状态和当前员工角色。主管、客服可以确认或拒绝授权院区内的有效待确认预约；医生、医护、护理、运营不能审批。停诊时段不能继续确认。

到诊登记与扫码仅开放主管、客服、医生和医护，继续执行院区与负责预约的数据范围检查。预约确认与实际到诊独立记录。护理、运营无签到操作权限。

## 停诊改期

预约详情显示停诊原因，可进入到诊工作台的对应日期待改期队列；「全部停诊待改期」查询全部日期。

操作员工先与患者确认安排，选择同医生、同院区的未来开放且有名额时段，填写患者同意改期的沟通记录。原预约必须为停诊时段的待确认或已确认记录，且尚未到诊或治疗。保留预约编号与关联诊疗资料；已确认状态保留，待确认重新计算确认截止。满额、关闭、过期目标、版本冲突或重复占号时整笔操作回滚。

接口：`POST /api/v1/admin/appointments/{appointmentId}/suspension-reschedule`，请求字段 `slotId`、`version`、`reason`、`requestKey`。重试相同请求键不会重复转移名额或写审计；同键改变目标或沟通内容返回冲突。事务同时转移预约占号、修改预约版本并写入 `suspend-move` 事件，记录原时间、新时间、沟通记录与操作员工。患者预约操作记录可查看改期结果。

## 到诊工作台

默认显示北京时间当日待到诊预约，支持日期、授权院区、医生、待到诊/已到诊/停诊待改期/全部预约筛选及分页。页面可见且无操作时每 30 秒刷新。手工登记须核实患者实际到院，系统保存当前时间；原预约详情仍支持核实后的历史补录。

预约列表接口新增 `clinicId`、`arrival=expected|arrived`、`needsReschedule=true`。筛选先在数据库应用数据范围，再分页计数。`slotStatus`、`suspensionReason` 和操作能力随预约返回。

## 扫码签到

患者本人通过 `POST /api/v1/me/appointments/{appointmentId}/check-in-code` 领取 PNG 二维码。只有当天、已确认、未到诊、未治疗且开放时段的预约可领取；签到码有效 5 分钟，数据库只保存随机令牌摘要和预约版本。二维码不包含姓名、手机号或登录令牌。

后台支持摄像头及扫码枪输入。`POST /api/v1/admin/arrival-scans/resolve` 核对二维码并返回有权查看的预约，员工核对患者、医生与院区后调用 `/confirm` 登记到诊；两者请求均为 `{token}`。重复确认仅产生一次实际到诊及审计。改期、取消、记录版本变更、停诊或过期会使未使用的旧码失效；网络响应丢失可用原码重试。到诊登记不释放预约名额，后续治疗按原有流程释放。

微信图片写入应用自身文件目录显示。二维码到期需点击「刷新签到码」；真机摄像头、扫码枪及微信端实机扫描仍需设备验收。

## 升级与验证

新增迁移 `00042_arrival_checkin.sql` 与 `00060_appointment_event_sequence_upgrade.sql`，先运行全部待执行迁移并重启 API。迁移60兼容已执行旧版迁移29的数据库，补齐操作记录排序列。迁移不修改历史预约或推定历史到诊。

```powershell
pnpm contracts:check
pnpm typecheck
pnpm build
pnpm exec playwright test tests/arrival-workbench.spec.ts --output=.local/arrival-e2e-results
. ./scripts/common.ps1
Import-ProjectEnv
Push-Location services/api
go test ./internal/store ./internal/httpapi -run 'Test(CheckIn|SuspensionReschedule|ArrivalWorkbenchPermissions)' -count=1
go vet ./...
Pop-Location
```

MySQL 测试只允许专用 `_test` 数据库，使用虚构患者。覆盖患者所有权、院区范围、二维码到期、并发重复签到、真实 HTTP 签到链路、满额改期回滚、成功后的名额与状态、幂等审计和角色权限。浏览器回归覆盖客服审批、扫码核对后确认、停诊改期时段选择与沟通记录校验。摄像头权限被拒绝时保留扫码枪/手工核对入口。
