## 部署材料

- Docker 构建上下文：`services/api`，其中包含 `Dockerfile`、`.dockerignore`。
- 配置模板：`deploy/cloudrun.env.example`。密钥在云端私有环境变量中填写，不打包本地 `.env`。
- 打包：`pwsh -NoProfile -File scripts/package-cloudrun.ps1`。输出在 `.local/cloudrun/bailiankai-api-source.zip`；重复执行会更新该源码包。
- 容器监听 `0.0.0.0:8080`，控制台服务端口填写 `8080`。使用非 root 用户运行。
- 运行模式 `APP_ENV=cloudrun`，强制 `ENABLE_DEMO=false`、COS 图片存储，关闭 `/api/v1/dev/patient-sessions`。本地开发模式继续只允许 loopback。
- 云端管理后台需通过 `ADMIN_ALLOWED_ORIGINS` 精确允许 HTTPS 来源，例如 `https://admin.example.com`，多个以逗号分隔。保留本机 HTTP 开发页面访问，便于本地后台验收云 API。无 Origin 的小程序请求不依赖 CORS；所有业务身份鉴权继续由 API 执行。

## 首版资源配置

1. 创建独立服务 `bailiankai-api`，不覆盖已有业务服务。优先选与现有云开发环境一致的上海地域；资源能否复用需登录控制台核实。
2. 当前依赖进程内后台循环，最小实例数和最大实例数均设置为 `1`，不使用缩容至零。这会持续产生实例费用，实际规格、报价需在控制台核对后确认。
3. 同地域 VPC 内的 MySQL，私有 COS 桶开启版本控制与禁止公共访问。不能把当前电脑 loopback 数据库地址填入云环境。
4. 就绪检查路径 `/readyz`（会检查数据库与图片存储）；存活检查 `/healthz`。初始化迁移完成后再切入业务流量。

## 初始化与发布顺序

1. 确认云环境、MySQL、COS、VPC 连通性及凭据。已有数据库只增量迁移，不自动清空或覆盖。
2. 构建镜像。当前工作环境没有 Docker，需用云端构建或提供 Docker 后验证完整构建。
3. 使用同一镜像的 `/app/migrate` 独立执行数据库迁移；不能把迁移放在每次 API 启动路径。
4. 初始化正式门店和员工账户。镜像提供 `/app/bootstrap-employee`，需设置 `EMPLOYEE_CREDENTIALS_FILE` 为运行身份可写的私有文件路径，并在临时实例被回收前安全取回凭据；没有已有账户时该命令创建主管。其展示名仍为“本地主管”，初次登录后可在后台调整。禁止运行演示 seed。
5. API 服务执行默认 `/app/api`。确认版本与就绪，再开启前端验收访问。首次开放公网/配置资源权限需根据具体影响确认。
6. 验证登录与越权、预约、文件上传读取、通知/导出/AI 任务无人访问时仍执行，以及实例重启后的任务恢复。真实微信、真实 AI 效果仍需配置后单独验收。
7. 更新小程序 `apps/miniprogram/app/config/api.ts` 与后台 API 地址，设置 HTTPS 合法域名。
