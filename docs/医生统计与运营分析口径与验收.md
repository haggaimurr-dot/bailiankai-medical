# 医生统计与运营分析（v1）

后台入口：**医生统计与运营分析**（`/overview`）。主管、运营可按授权院区、医生、起止日期查询，按医生、院区或每日分组。默认查询北京时间本月1日至当天，日期含首尾，单次最多366天。

## 日期、归属与计数原则

这是按日期归属的队列统计，反映查询时的记录与状态。预约指标按**计划就诊日期**（排班 `starts_at`）归入范围；随访指标按**计划随访日期**（任务 `due_at`）独立归入范围。不是按确认、到诊、治疗或回评动作发生时间统计的流水。

例如9月30日的预约于10月1日登记到诊：查询9月仍可看到这次到诊；该预约10月3日的随访任务计入10月随访。之后的登记、回评、异常处理会更新同一日期范围的结果。

医生与院区归属以预约排班为准。随访负责人改派、离岗交接不改变接诊医生的统计。停用院区与医生仍可查询授权范围内的历史数据。预约与任务分别聚合，确认事件、治疗修订和多个随访任务不会放大预约次数。

## 指标定义

| 指标 | v1定义 | 单位 |
| --- | --- | --- |
| 全部预约 | 区间内计划就诊的全部预约，包含取消、拒绝、过期 | 次预约 |
| 待确认预约 | 当前为pending且尚未超过确认截止 | 次预约 |
| 预约确认 | 曾发生人工confirm事件的预约，含后来取消；历史confirmed/completed状态兜底，每条只计一次 | 次预约 |
| 实际到诊 | 有独立`arrived_at`登记的预约，确认和实际治疗均不自动推定到诊 | 次预约 |
| 实际治疗 | 存在实际治疗记录的预约，治疗更正仍计一次 | 次预约 |
| 随访任务 | 区间内计划随访的任务，包括尚未到计划时间的任务 | 项任务 |
| 随访完成 | 状态reviewed或handled；患者提交反馈submitted或异常待处理alert不算完成 | 项任务 |
| 逾期未提交 | 计划时间早于查询时点且仍pending；已提交待回评不计入 | 项任务 |
| 异常任务 | 状态alert或handled | 项任务 |
| 异常已处理 | 状态handled，业务流程要求医护回评和实际处理记录 | 项任务 |
| 异常待处理 | 状态alert | 项任务 |
| 到诊率 | 实际到诊 / 预约确认 × 100% | 百分比 |
| 随访完成率 | 随访完成 / 随访任务 × 100% | 百分比 |
| 异常处理率 | 异常已处理 / 异常任务 × 100% | 百分比 |

分母为0时API返回null，页面显示“—”，表示不适用。汇总比率通过合计分子、分母重新计算，不平均各医生的比率。历史治疗没有到诊登记时可能出现治疗数高于到诊数，因此不提供基于到诊数的治疗转化率。

## 独立到诊登记

预约详情提供到诊状态、实际到诊时间选择和登记入口。主管、客服、医生和医护角色可在各自预约访问范围内登记；护理与运营不可登记。只接受已确认或已治疗预约，不改变确认/治疗状态、不重复释放号源。

实际到诊时间不得早于预约创建或晚于当前时间；已有治疗时不得晚于实际治疗时间。录入或更正治疗也不得把治疗时间改为早于已登记到诊时间。已治疗且缺少到诊记录的预约可经核实后补录，系统不自动回填历史。

登记在事务内锁定患者、排班与预约，增加预约版本，保存实际时间、登记员工，写入`appointment_events`的`arrive`事件（事件时间为登记时间）。相同实际时间重试幂等，即使版本已改变也不重复写事件；不同时间或陈旧版本返回409并提示刷新。已登记时间不提供覆盖编辑入口。到诊与取消并发只能一个成功；到诊之后患者不能取消。

## 接口与权限

- `GET /api/v1/admin/analytics?dateFrom=2026-10-01&dateTo=2026-10-04&groupBy=doctor`，可选`clinicId`、`doctorId`，分组支持`doctor`、`clinic`、`day`。
- `POST /api/v1/admin/appointments/{appointmentId}/arrival`，JSON包含`version`和带时区的`arrivedAt`。
- 旧`GET /api/v1/admin/overview`计数接口保留。

分析报告含口径版本、时区、查询时点、日期范围、汇总、分组与授权筛选选项，不返回患者姓名、手机号、诊疗摘要或照片。授权选项和指标在同一只读REPEATABLE READ事务查询，汇总与分组一致。无授权返回空选项与零汇总；筛选未授权或不存在的医生/院区统一404。角色非主管或运营不能访问分析接口。

前端仅使用统计接口提供的授权选项。修改筛选后保留结果查询快照并提示重新查询；新请求开始或失败隐藏旧结果；较早请求的迟到成功/失败不覆盖新请求。

## 升级与验收

需应用`services/api/internal/database/migrations/00026_appointment_arrival.sql`并重启API；已有确认、治疗和患者资料保持原记录。

覆盖范围：

1. 确认与到诊分开，completed且未登记到诊不计入实际到诊。
2. 同时间登记重试、不同时间冲突、时间边界、已治疗补录、登记与取消并发、治疗时间回退拒绝。
3. 确认事件重复、治疗修订、多随访任务不会重复计预约。
4. 北京时间跨日及区间首尾、跨月随访独立归属、无数据日期补0。
5. 医生/院区筛选、任务改派、停用历史资料、无授权、越权与0分母。
6. 页面查询快照、失败重试、迟到响应保护、非上海浏览器时区的到诊时间转换。

验证命令：`pnpm contracts:check`、`pnpm typecheck`、`pnpm --filter @bailiankai/admin build`；Go测试设置专用`*_test`库的`TEST_DB_DSN`后运行`go test ./internal/store ./internal/httpapi -run 'Arrival|Analytics' -count=1`；浏览器运行`pnpm exec playwright test tests/analytics.spec.ts tests/arrival.spec.ts`。浏览器使用接口mock验证交互，真实数据库测试验证计数、事务和权限。
