# 后台患者档案与问诊模板

患者档案页面（`/patients`）提供“新建患者档案”入口，无需先创建预约。管理员、医生和兼容医护角色可以建档、编辑基本资料与标签、保存问诊及模板；护理角色只查看有权访问的档案。

## 使用流程

1. 点击“新建患者档案”，填写姓名、所属院区，可补充性别、出生日期、联系手机号和患者标签。保存后自动打开该患者档案，可立即记录问诊。
2. 问诊按肤质、患者诉求、既往病史、过敏史和既往治疗史分别录入，保留原有病史备注、评估和处理建议。复诊必须关联同一患者、同一院区的既往问诊；关联预约仍是可选项。
3. “存为模板”保存当前通用问诊内容和初诊/复诊类型。模板不保存患者编号、预约、复诊关联、时间或阶段进度。选择模板后点击“应用模板”，仅填充空白正文，仍需核对患者实际情况。模板可删除。
4. “编辑资料 / 标签”修改姓名、性别、生日、人工登记联系方式和标签。最多20个标签，每个最多24字，不能重复。目录支持按标签精确筛选，筛选在后端分页前执行。

## 权限与数据

新增迁移 `00044_patient_charts.sql`，建立 `patient_charts` 和 `consultation_templates`，扩展问诊结构化字段。启动服务前按项目原有迁移流程执行。档案资料按版本更新，过期版本返回409，避免覆盖他人修改。

独立建档以院区和建档医护负责人限定访问；管理员在授权院区内可访问，医护可以访问本人建档或原有预约/随访范围中的患者。既有预约范围继续保留，照片授权规则继续生效。模板按院区限制，管理员可管理授权院区内模板，医生/医护查看本人关联员工账号所建模板，删除限本人创建的模板。

人工登记联系手机号独立保存，不生成微信手机号授权，也不通过手机号匹配、合并微信患者身份。人工档案通过患者本人确认的绑定码关联小程序账号。

## 人工档案绑定微信身份

1. 建档后，在患者详情点击“微信身份绑定”。后台显示“未绑定微信 / 已绑定微信”，仅管理员、医生和兼容医护角色可对有权访问且具有结构化资料的档案生成绑定码。
2. 核对患者本人后生成绑定码并交给本人。绑定码15分钟有效、一次性使用；重新生成立即使旧码失效，也可撤销全部未使用的绑定码。原始绑定码只在生成时返回，数据库仅保存摘要。
3. 患者登录微信小程序，在“我的资料 → 绑定院内档案”粘贴绑定码，核对姓名、院区和患者编号后确认。预览不返回手机号、问诊内容或微信OpenID。
4. 成功后沿用人工档案患者编号、姓名、标签及全部问诊和诊疗记录。微信验证身份、账号手机号授权及隐私同意历史关联到该档案；人工联系方式独立保留。旧登录身份的所有设备会话失效，当前设备取得新会话；其他设备重新登录同一微信账号即可恢复档案。
5. 微信账号已有预约、诊疗、人工档案、收藏、消息或客服等业务记录时返回身份冲突，不自动合并。只有空登录账号（允许已设置姓名、微信手机号与隐私同意）可以绑定。冲突时整个事务回滚，原账号及会话、预约、授权记录和绑定码保持原状态。
6. 档案已经绑定或生成码后资料发生修改时，旧码不能继续绑定。医护刷新核对后重新生成。绑定请求响应丢失时，患者重新微信登录可恢复已经绑定的档案。当前流程不提供解除绑定或自动合并既有患者记录。

新增迁移 `00070_patient_binding.sql`，记录生成医护、生成时间、有效期、使用时间及原登录患者编号。并发使用同一个码只允许一个微信账号成功。开发与测试环境的数据库迁移由原有启动流程执行；真实微信操作仍需已有微信登录配置。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/v1/admin/patients` | 直接建档 |
| PUT | `/api/v1/admin/patients/{patientId}/profile` | 更新资料和标签，包含版本号；0为既有患者首次补充资料 |
| POST / DELETE | `/api/v1/admin/patients/{patientId}/wechat-binding` | 生成 / 撤销绑定码 |
| POST | `/api/v1/me/patient-binding/preview` | 当前微信患者凭绑定码核对档案 |
| POST | `/api/v1/me/patient-binding` | 按预览版本确认绑定，返回新患者会话 |
| GET | `/api/v1/admin/patients?tag=标签` | 按标签精确筛选患者 |
| GET / POST | `/api/v1/admin/consultation-templates` | 查询/保存模板 |
| DELETE | `/api/v1/admin/consultation-templates/{templateId}` | 删除模板 |

现有问诊创建接口增加 `medicalHistory`、`allergyHistory`、`treatmentHistory`、`skinType`、`goals`，旧客户端仍可按原字段提交。结构化字段在档案记录中回显。

## 验证

`tests/patients.spec.ts` 覆盖原有问诊/复诊、直接建档、结构化提交、模板持久化和应用空白字段、资料及标签更新、刷新和标签筛选。HTTP单元测试覆盖角色权限、手机号/日期/标签校验和问诊字段长度。MySQL集成测试覆盖无预约建档的读写权限、标签筛选、版本冲突和模板院区隔离，需配置专用测试数据库 `TEST_DB_DSN`。

绑定专项测试另覆盖后台生成、重新生成、撤销与状态刷新；绑定成功后微信登录恢复人工编号、保留问诊、手机号及隐私历史；过期码、资料变化、角色与院区隔离、已有业务记录回滚、重复和并发使用；小程序迟到响应不得覆盖新身份。
