# 案例库接口与验收

已接入后台案例整理、1–3组治疗前后图片关联、患者独立案例展示授权、医生审核、主管发布与撤回，以及小程序案例列表与详情。需要数据库迁移 **24**。入口：后台“案例库”、小程序首页“案例库”、“我的资料 → 我的案例”。

## 业务规则

1. 主管从已治疗预约创建案例，填写标题、摘要、展示正文，选择面诊照片与已提交随访照片。每组须属于同一患者、同一预约、同一角度；前图不晚于治疗时间，后图不早于治疗时间；同一角度只允许一组。
2. 关联原图须有当前 `photo-care-v2` 诊疗照片授权。服务端校验大小和摘要后生成独立私有副本，将副本编号冻结在内容版本中。原诊疗照片替换、删除或撤回诊疗授权不会改写案例副本，也不会自动撤回独立展示授权。
3. 患者在“我的案例”查看完整文案、全部图片和独立授权正文，决定是否同意本版本展示。图片未完整显示时不能同意；图片故障不阻止撤回原有授权。只有患者本人能授权和撤回，员工不得代替患者确认。
4. 用途限定为百莲凯小程序案例展示。服务器保存 `case-display-v1` 正文、患者身份、时间、内容快照和图片编号。隐私同意、诊疗照片授权、案例展示授权分别记录；拒绝展示不阻止诊疗业务。
5. 在岗医生审核，拒绝必须填写意见；主管维护、发布和下架，不能代替医生审核。发布要求当前内容版本已独立授权、审核通过、所属院区启用并已公示。护理、客服、运营无案例后台权限。
6. 医生的案例审核范围是获授权院区，独立于其日常主诊患者范围；案例入口不授予原始临床档案权限。跨院区或跨患者详情返回404。
7. 修改文案或图片立即停止公开展示，递增 `revision`，清除展示授权和审核，重新走完整流程。分类和标签属于内容快照，修改它们同样触发上述流程。所有普通写入要求当前 `version`，授权绑定 `consentRevision`。

## 撤回与图片

- 主管下架或患者撤回授权后，公开列表、详情和旧图片地址停止后续访问。撤回不删除临床记录、不改变诊疗授权；再次同意不会自动发布。
- 患者撤回允许旧页面正整数版本号，避免并发更新阻止撤回。发布/撤回按相同预约、案例顺序加锁，两种提交顺序最终均不会留下未授权公开案例。
- 图片没有静态地址或对象存储直链。读取检查当前案例状态和图片归属，在存储读取后再次核对；全部响应禁止缓存。公开响应不包含患者、预约、原图、员工编号的值。后台文案须人工去除姓名和联系方式；图片可能使患者被识别，授权正文明确告知。
- 小程序公开列表/详情每10秒重新查询，失败或撤回清除文字与临时图片，隐藏页面清除资料。后台图片沿用10秒重新鉴权、15秒预览期限。已发送的字节、截图及他人保存的内容不能追回。
- 私有副本和历史版本作为审计资料保留，纳入图片引用目录、清理、备份及恢复；失败事务留下的无引用副本由现有24小时孤立对象清理回收。

## 接口

下列路径前缀为 `/api/v1`，`/me` 使用患者会话，`/admin` 使用员工会话，公开查询无需登录。JSON响应包含 `data`。

| 方法与路径 | 输入与行为 |
| --- | --- |
| `GET /cases`、`GET /cases/{resourceId}` | 当前已授权、审核通过、已发布且院区可展示的案例。 |
| `GET /me/cases`、`GET /me/cases/{resourceId}` | 本人案例，包括待授权、未发布和已撤回。 |
| `POST /me/cases/{resourceId}/consent` | `version, granted, policyVersion`，授权版本 `case-display-v1`。 |
| `GET /admin/cases`、`GET /admin/cases/{resourceId}` | 授权院区工作区，列表支持 `status=published/unpublished`。 |
| `POST /admin/cases` | `appointmentId, title, summary, body, pairs`，每组 `beforeSourceId, afterSourceId`；返回201。 |
| `PUT /admin/cases/{resourceId}` | `version, title, summary, body, pairs`。 |
| `POST /admin/cases/{resourceId}/review` | `version, decision, note`，`approved/rejected`。 |
| `POST /admin/cases/{resourceId}/publish`、`/unpublish` | `version`。 |
| `GET /admin/cases/{resourceId}/history` | 倒序历史，含操作者与授权快照。 |
| `GET /cases/{resourceId}/images/{imageId}/content` | 公开当前案例图片，撤回后404。 |
| 对应 `/me/cases/.../images/.../content`、`/admin/cases/.../images/.../content` | 本人或授权案例管理角色查看工作区图片。 |

列表新增可选 `category/tag` 精确筛选；两者同时输入为联合筛选，仅在当前调用者有权读取的案例中查询。分类最多40字；标签最多10个、每个1–30字，首尾空白清理并去重；旧案例返回空分类与空标签数组，显示“未分类”。创建/修改可省略这两个字段以兼容旧请求。分类标签保存在已有 `content_json`，无需额外数据库迁移。

后台候选预约通过 `GET /admin/appointments?status=completed&q=...&page=...&pageSize=20` 查询，`q`最多100字，按预约编号、姓名或手机号字面包含搜索，保留现有院区与职责限制；选择预约后仍需通过治疗、诊疗授权、同角度、前后拍摄时间及随访提交校验。

列表支持 `page/pageSize`（默认1/20，最多100）及可选 `clinicId`，返回 `meta.page/pageSize/total`。标题1–200字、摘要最多1000字、正文1–20000字；纯文本显示。未知字段及伪造授权字段被拒绝。授权、审核或图片关联不符返回409，版本竞争返回409。
