# 后台员工与权限

主管在「员工与权限」管理个人账号，创建账号、调整角色与关联人员、选择授权院区、启停账号、重置密码、查询账号操作记录，并查看六类角色的权限矩阵。所有已登录员工均可从顶部「修改密码」进入个人改密页面。

## 权限入口

登录和会话接口返回 `capabilities`。菜单、路由及预约审核/排班编辑按钮统一读取后端计算结果，页面切换重新验证会话。后端由同一 `allowedEmployeeOperation` 检查接口授权；无权页面跳转至该账号可访问的首页。新增页面须在 `employeeAccessRules` 中关联实际操作，以同步菜单与权限矩阵。医生公开资料对所有角色可见；患者资料仍由院区、接诊医生及随访负责人范围约束。

`GET /api/v1/admin/permissions` 返回角色权限矩阵，按角色标记页面入口及主要业务操作。矩阵展示角色能力，不保证对任意患者记录具有操作权限。

## 调整既有账号

`POST /api/v1/admin/employees/{employeeId}/access` 接收 `version`、`role`、`staffId`（取消可选关联传空字符串），仅主管可调用。医护必须关联人员，医生/护理角色须匹配人员类型；人员须在岗且未被其他账号占用。目标账号及关联人员受主管管理范围约束。当前主管不可自行降权，最后一个启用主管不可被降权。

保存后版本递增、所有旧会话撤销，记录 `access-updated` 审计。关联人员调整不会转移原人员的诊疗或随访任务，请先通过人员交接处理既有待办。院区调整继续使用既有 `/clinics` 接口，界面改为院区名称多选。

## 个人改密

`POST /api/v1/admin/session/password` 仅针对当前会话本人，接收 `currentPassword`、`password`。新密码 UTF-8 编码长度为 12–72 字节，须与原密码不同；前端另校验两次新密码一致。校验原密码、版本、更新哈希、撤销全部会话和记录 `password-changed` 审计在同一事务中完成。原密码错误返回 `INVALID_CURRENT_PASSWORD`，不会撤销会话；账号版本变化返回 409。

## 数据库与验证

需执行迁移 `00050_employee_access.sql` 扩展审计动作约束。使用仓库正常迁移命令，不需要修改已有账号资料。

- Go 接口测试：`go test ./internal/httpapi -run TestEmployee`（在 `services/api` 运行）。
- MySQL 集成测试：`go test ./internal/store -run TestEmployeePasswordAndAccessRevokeSessions -v`，需专用 `_test` 数据库的 `TEST_DB_DSN`。
- 浏览器测试：`pnpm exec playwright test tests/employees.spec.ts`（需前端开发服务）。
