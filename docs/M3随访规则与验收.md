# M3 治疗与随访规则

本阶段仅为本机演示，使用虚构患者资料。后台已改为个人员工账号和会话，并有随访负责人分配与离岗交接；尚无生产部署；随访模板由主管配置并由医护核对，具体消息能力见消息模块文档。

## 治疗记录

- 从已确认预约录入实际治疗；预约时间不会自动当成治疗发生时间。实际治疗时间由医护确认，不得在未来，按北京时间显示。此演示允许补录及提前治疗，尚无到院签到校验。
- 必须选本预约的已发布方案版本，不能引用草稿或其他预约的方案。治疗记录保留版本编号，后来发布的方案不修改本次依据。患者查看方案时标出本次治疗依据版本。
- 摘要 1–1000 字，补充记录最多 2000 字，患者可见。
- 每个预约只记录一次治疗；多次到院分别建立预约。已记录内容可通过“更正治疗记录”生成新版本，原始版本和每次更正均保留，不能直接覆盖历史。
- 医护指定治疗后 1–90 天的随访时间，最多 8 次、不得重复。界面 1/3/7 天只是演示初值，应由医护调整，不是临床建议。
- 保存记录、生成全部任务、将预约标为 `completed`（已治疗）、释放预约占号、写入审计在同一事务。失败全部回滚；相同资料重试返回原记录，不重复建任务，不重复释放名额；不同资料返回冲突。
- 已治疗不能取消预约。尚未完成的预约继续遵循 M1 规则。

## 随访负责人和离岗交接

- 演示名册包含两位医生和一位随访护士；记录治疗时，医护为全部新随访任务指定一位在岗负责人，默认选预约医生。患者和后台均可看到当前负责人。
- 后台可按负责人筛选任务，并在任务详情选择另一位在岗人员、填写原因后改派。改派保留初始分配与每次变动记录；旧版本请求返回冲突，相同改派重试返回既有结果。
- 人员离岗时必须选择另一位在岗接手人并填写原因。全部 `pending`、`submitted`、`alert` 任务在同一事务内交接并记录逐任务历史；已回评或已处理任务保留原负责人。离岗者不能接收新任务。恢复在岗不自动取回已交接任务。
- 员工使用个人账号登录；主管可改派、离岗交接、恢复在岗，记录员工编号和姓名。医护账号必须关联名册人员，人员离岗后其后台会话失效。既有演示历史仍显示原演示操作者；真实员工账号须由主管按实际人员开通。
- 改派和离岗交接的新接手人须有启用中的关联员工账号。每条转移的任务生成一条待确认交接；接手人登录后逐条确认，记录确认账号和时间。主管可按状态和接手人查看待确认、已确认及已转出的交接。
- 若任务在确认前再次转给他人，旧交接标为“已转出”并保留历史，新接手人获得新的待确认交接。确认时再次核对任务当前负责人和交接版本，旧接手人不能确认已转出的任务。该确认机制从迁移 10 后新发生的改派和离岗交接开始，不为此前历史补造确认记录。
- 主管可设置交接确认超时时限（1–720 小时，默认 24 小时）。交接创建后超过时限仍待确认的记录在主管页面标红，显示超时总数，并可只看超时记录。时限是所有主管共用的数据库设置；修改后按新时限重新计算，不改变交接状态，也不自动改派。
- 主管可为超时交接逐次记录跟进措施和处理结果，每条记录保留主管账号和记录时间，不覆盖旧记录。交接后来确认或转出，原有跟进历史仍可查看并补记最终结果；未曾超时的交接不能新建跟进记录。记录仅主管可见，不会自动发送消息或改变任务负责人。
- 每次主管跟进需选择“待回复”“需处理”或“已解决”，状态随记录写入历史，当前状态单独保存在交接上。超时但未跟进的交接，以及状态为待回复或需处理的交接进入主管待办；即使接手人后来确认或任务转出，仍须由主管记录已解决才退出待办。已解决后可通过新记录重新进入待办。迁移 13 将此前已有跟进但未结构化的交接标为需处理。

## 员工资料访问范围

- 主管可查看全部预约与随访资料。医护账号只能在后台预约列表看到自己接诊的预约，或自己当前负责的随访任务所关联的预约；直接请求其他预约的详情、方案、照片或治疗记录返回不可访问。
- 随访队列只返回当前负责人为本人的任务；回评、任务历史和随访原图也要求任务当前仍归本人。交接后旧负责人不能用旧页面继续回评或读取照片，服务端在回评事务中再次核对负责人。
- 接诊医生可记录和更正自己预约的治疗、编辑和发布方案；护理人员可查看其随访任务关联的预约资料，但不能编辑治疗或方案。患者端继续仅限患者本人会话。

## 治疗记录更正

- 更正须填写 1–300 字原因，并提交当前治疗版本号；旧版本的不同更正返回冲突，相同更正重试返回既有结果，不重复生成版本。
- 可更正实际治疗时间、本预约已发布的方案依据、摘要和补充记录。服务端重新校验方案归属与时间不得在未来。原始录入时间不变，每个版本保存完整快照、原因、操作时间和演示操作者。
- 若治疗时间改变，尚未填写且没有照片的随访任务按原间隔整体调整到期时间，并提高任务版本。已有任一随访反馈或照片时，治疗时间锁定；方案依据与文字仍可通过新版本更正。现有任务、照片和患者反馈均不会删除。
- 患者本人和已登录员工在随访详情可查看当前版本及完整历史；其他患者不能读取。员工登录与版本操作者可追溯，但尚无院方正式签发和审核流程。

## 患者反馈与照片

- 本人可看随访队列、预约下任务、治疗记录及医护结果；其他身份无法访问。
- 任务初始 `pending`，到期未提交显示逾期，但仍可提交；支持提前反馈。未接微信提醒，页面显示不会自动通知患者。
- 需填写症状描述（1–2000 字，包括“没有不适”）并选当前感受。照片选填，不阻断反馈。
- 感受为“明显/严重不适”（值 2/3）或主动请求重点关注时为 `alert`，否则 `submitted`。这是患者反馈的队列规则，不是诊断。
- 每个任务分别存正面/左侧/右侧照片。每角度保留一张，提交前可替换，提交后冻结，不覆盖其他任务或面诊照片；未提交照片也有上传审计。
- 统一使用 M2 私有媒体处理：8 MB JPG/PNG、最长边 4096、服务端重编码为 JPEG、去除源元数据。图片没有公开 URL。
- 授权升级为 `photo-care-v2`，覆盖本次预约的诊疗和治疗后随访照片。已有 v1 授权不自动扩展，患者必须重新同意。授权/撤回仍保留版本和时间。
- 患者可在已治疗后授权或撤回；撤回后医护列表不返回照片，原图接口拒绝，患者保留本人查看能力。医护详情每 15 秒刷新当前任务授权，也可主动刷新。已显示/已下载的内容不能远程抹除。
- 治疗后的面诊照片仅供查看；新的恢复照片放入随访任务。
- 重复提交相同内容找回原结果；不同内容不可覆盖已提交反馈。页面网络失败时保留当前填写内容，可重试或刷新核对。尚未提交的文本只保留在当前页面，退出后没有持久草稿。

## 医护回评及异常

| 当前状态 | 操作 | 要求 | 结果 |
|---|---|---|---|
| `pending` 待提交 | 医护查看/跟进 | 患者尚未提交，不能回评 | 状态不变 |
| `submitted` 待回评 | `review` | 回评 1–2000 字 | `reviewed` 已回评 |
| `alert` 异常待处理 | `handle` | 回评及 1–1000 字实际处理记录 | `handled` 异常已处理 |
| `reviewed` / `handled` | 查看 | 已完成，只读 | 状态不变 |

异常不能通过普通回评直接关闭。回评与处理记录对患者可见；操作审计记录当前员工账号，但不表示院方正式签发。并发回评只有一个成功，另一个返回 409；同一操作丢失响应后可安全重试。

队列提供全部/待提交/逾期/待回评/异常待处理/已回评/异常已处理及负责人筛选和分页，异常优先排列。治疗、更正、负责人变动、上传、提交、查看及回评/处理写入审计。后续仍需提醒机制、正式签发身份与院方审核流程。

## 后台配置与独立护理反馈（2026-10-07）

- 随访天数使用可增删的标签配置，限制为治疗后 1–90 天、最多 8 次且不得重复，按天数排序。录入治疗时显示对应北京时间日期；切换预约恢复初值 1/3/7，应用模板后仍可调整。
- 随访任务队列提供到期日期范围入口，按北京时间自然日包含起止日筛选；日期变更重置分页，可清空日期。负责人和状态筛选仍同时生效。
- “随访模板”页签提供按院区共享的名称、天数、回评文本和异常处理参考文本。主管可新增、编辑、启用或停用；医护只能查看和应用。修改校验版本号，保留完整快照及操作账号，不改变已生成任务或已发送回评。
- 治疗录入仅显示预约院区启用模板，点击“应用随访天数”后填入日程；任务回评点击“应用回评内容”后填入可编辑文本。医护须核对实际情况，异常处理参考文本不能代替真实处理措施。
- “护理反馈”页签提供独立预约列表，在已确认或已治疗预约下追加护理发生时间、护理情况/患者反馈及实际措施/跟进安排，无需绑定随访任务或等待患者提交。护理反馈仅供后台员工查看，不改变治疗、随访或预约状态。
- 护理记录保留录入人、发生时间和保存时间，不提供覆盖或删除。历史可按护理发生日期筛选。网络失败保留内容；相同请求键和内容重试返回原记录，改变内容返回冲突。
- 模板限授权院区；护理反馈遵循现有预约访问范围。主管可访问授权院区，医护只能访问本人接诊或本人当前负责随访关联的预约，客服及运营不可访问护理反馈。
- 数据库迁移：`00046_followup_tools.sql`。部署/本地启动前执行既有 `go run ./cmd/migrate`，无需额外依赖。
- 验证：`tests/followup-tools.spec.ts` 覆盖日期请求、清空筛选、重复天数、模板保存、应用天数生成任务及护理反馈失败重试；`TestFollowupToolsMySQL` 使用真实 MySQL 测试模板版本/快照、院区隔离、护理去重和日期筛选；`TestFollowupToolsPermissionsAndOffsets` 验证角色权限和天数边界。


## 正式护理及随访规范配置（2026-10-08）

- 后台“护理与随访规范”页签扩展原随访模板，增加适用治疗（最多 200 字）、护理要求（最多 2000 字）、随访检查要点（最多 2000 字）及草稿/正式规范状态；保留随访天数、回评文本及异常处理参考。
- 主管可保存未完成的草稿。设为正式规范时，适用治疗、护理要求、检查要点、回评文本和异常处理参考必须全部填写；草稿不可启用。正式规范可停用，也可改回草稿，均保留版本及修改快照。
- 医护只可查看和应用。本院区已启用的正式规范才进入治疗、回评和护理参考选择器；护理参考展示护理要求、检查要点及异常处理，不自动填写已执行措施。治疗和回评应用仍由医护主动点击并核对，不改变历史任务和记录。
- 迁移 `00063_formal_care_standards.sql` 为既有模板增加新字段，原内容及启用标记保留，但状态为草稿，在完善为正式规范前不进入应用列表。页面按有效状态显示停用，主管保存草稿时统一写入停用标记。部署前执行 `go run ./cmd/migrate`。
- 本功能提供院区规范配置与使用入口；具体规范由院区填写确认，系统不自动生成临床护理内容。
