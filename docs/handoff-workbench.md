# 人员交接与待办工作台

- `/workbench`：交接待确认、主管超时升级与跟进待办、随访待回评和异常处理，入口携带对应状态筛选。分类会有重叠，不相加为总任务数。
- `/handoffs`：交接确认与跟进、人员离岗交接、提醒设置分为三个工作区。医护只能确认自己的交接；离岗交接与设置由主管操作。
- `/followups`：保留治疗、随访回评和任务改派。人员交接及主管跟进迁到专用入口。

交接事务同时创建接手人的站内通知，失败则整个交接回滚。通知与交接状态独立：标为已读不代表确认收到，查看通知可定位对应交接。顶部入口显示未读数，页面可见时每 30 秒刷新。

API 启动后每分钟扫描未确认、未结案的超时交接，按现有全局时限判断；默认 24 小时，主管可设置 1–720 小时。仅通知启用且拥有该任务院区授权的主管。同一交接、同一主管、同一种通知有数据库唯一约束，重启和多实例扫描不会重复创建。已确认、已转出或已解决的交接不再生成升级通知；已发送通知保留历史状态。调整时限后按新时限扫描。

通知渠道为后台站内通知。小程序患者消息使用独立的既有通知流程。

上线前按现有流程运行 `go run ./cmd/migrate`，应用 `00040_handoff_notifications.sql` 后启动 API。接口及类型同步在 `packages/contracts/openapi.yaml`、前端生成类型和 Go 生成类型中维护。

验收：`pnpm exec playwright test tests/handoffs.spec.ts`；`go test ./internal/httpapi -run HandoffNotification`。MySQL 集成验收为 `TestHandoffNotificationsMySQLIntegration`，需设置专用 `_test` 数据库的 `TEST_DB_DSN`，覆盖事务通知、改派重试、超时边界、去重、院区与账号权限、已读隔离以及确认后停止升级。
