# 医生资料与资质审核

本次使用 mock 数据验证流程。测试中的人物、证照编号、机构和附件均为模拟内容；不代表真实医生资质。院方尚未提供正式资料，未录入真实人员信息或执行实际资质核验。

## 使用流程

1. 主管进入后台 `/doctors`，新增或编辑姓名、职称、简介、擅长项目、头像、服务介绍和证照，保存草稿。
2. 点击“资质审核”，对照资料和证照图片核验；通过时至少提供一项完整证照（名称、编号、颁发机构和 HTTPS 图片地址），填写核验依据并勾选确认。退回须填写原因。
3. 审核结果保存后不会自动发布。正式资料仅审核通过后可从“预览与发布”发布；演示资料继续兼容原有发布方式，也可体验模拟审核。
4. 修改任何医生资料都会清除当前审核结果，需重新审核。启停和账号关联不修改资料内容，不清除审核结果。所有历史审核记录保留。

审核仅作用于当前草稿。审核退回或修改草稿不会覆盖上次发布的资料；若上次发布内容存在问题，可立即停用医生资料。小程序仅展示发布快照及其中通过审核的核验日期（北京时间），不返回内部核验依据、退回原因或审核账号。演示核验仍保留演示标识。

现有无 `presentation` 的旧资料保持兼容，不自动判定已审核。明确配置 `presentation.isDemo: false` 的正式资料须遵守审核发布校验。资料不提供自动证照真实性验证，主管必须完成院方核验。

## API 与升级

应用 `00061_doctor_qualification_review.sql` 后重启 API。迁移仅增加可空审核 JSON 列，不回填虚构审核、不改动已有发布资料。

`POST /api/v1/admin/doctors/{resourceId}/review`：仅主管、仅授权院区、携带当前版本号。

```json
{
  "version": 5,
  "status": "approved",
  "note": "MOCK：已核对模拟身份、职称、证照和所属院区；仅用于流程演示。"
}
```

`status` 为 `approved` 或 `rejected`，`note` 必填且最多 2000 字。服务器保存审核账号、时间及结果，递增版本，在同一事务追加 `qualification-approved` / `qualification-rejected` 历史；过期版本返回 409，越权院区返回 404，非主管返回 403。客户端资料保存接口不能写入审核字段。正式资料缺少审核或完整证照时发布返回 `QUALIFICATION_REVIEW_REQUIRED`。

## 验证

- 后台隔离 mock 交互：`pnpm exec playwright test tests/directory.spec.ts`，8 项通过，覆盖审核确认、正式发布门槛、修改后重审、退回原因及版本冲突，并回归原有草稿、历史、启停及账号关联。
- 小程序医生详情：`pnpm --filter @bailiankai/miniprogram test:doctor-detail`，7 项通过，覆盖核验日期按北京时间展示、失败后清空旧日期和医生预约入口。
- `pnpm typecheck`、`pnpm contracts:check`、Go 单元测试及 `go vet ./...` 通过；小程序构建通过。
- 数据库生命周期测试：`go test ./internal/store -run TestDoctorQualificationReviewLifecycle -count=1 -v`，需显式配置独立 `*_test` 数据库。当前实际执行被其他模块三个 `00063` 迁移文件重号阻断，尚未完成数据库验证。
- 全量 `pnpm check` 被科普列表的首页展示回归失败阻断；后台构建被评估模块导入生成 CommonJS 文件的导出识别问题阻断。以上并非医生模块专项验证通过的范围。
