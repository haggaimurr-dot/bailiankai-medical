# 图片私有存储与恢复

## 交付边界

已提供腾讯云 COS 官方 Go SDK 接入、孤立对象清理、加密快照、校验与恢复命令，以及部署机上的每日备份定时模板。当前尚未创建真实存储桶，云端权限、上传、下载和恢复演练待桶与凭据配置后执行。API 原有 development/ENABLE_DEMO 和本机监听限制仍在；此改动不代表整套服务已获正式上线能力。

## 创建和配置存储

创建业务桶与独立备份桶，桶名为 `bucketname-appid`，地域例如 `ap-shanghai`。两个桶都设为私有，启用「阻止公共访问」和版本控制；备份桶建议独立账号、异地保存。禁止公共桶策略、公共对象 ACL、公开 CDN、自定义公开域名和分享链接。应用只返回业务照片编号，所有图片由 API 鉴权后代理读取。

服务启动与 `/readyz` 检查桶 ACL、桶策略和版本控制。发现公共授权、权限不足、版本控制未开启或存储不可用时检查失败。ACL 检查不能替代云端的「阻止公共访问」和管理员 IAM 控制；应用身份不得拥有修改桶 ACL、策略、版本控制或历史版本永久删除的权限。写入明确使用 `private` ACL、SSE-COS AES256、Content-MD5，SDK另校验上传 CRC64，API读取校验数据库 SHA-256 与长度。

API 环境变量：

```dotenv
MEDIA_DRIVER=cos
COS_BUCKET=<业务桶名称-appid>
COS_REGION=ap-shanghai
COS_PREFIX=private-media
COS_SECRET_ID=<服务端专用身份>
COS_SECRET_KEY=<通过密钥管理注入>
COS_SESSION_TOKEN=<临时凭据时填写>
```

`MEDIA_DRIVER=local` 仅供开发。配置 COS 后漏设 driver 会拒绝启动，COS故障不会回退本地。密钥不得放入前端、小程序或公开仓库；采用最小权限 CAM 身份。当前环境变量凭据在进程启动时读取，临时令牌续期需重新注入并重启，不能配置过期临时令牌后无人维护。

API 身份需要业务前缀的 `GetObject`、`PutObject`、`DeleteObject`（创建删除标记，不永久删历史版本）、限定前缀的 `GetBucket`，以及 `GetBucketACL`、`GetBucketPolicy`、`GetBucketVersioning`。备份源身份可只读；备份桶独立身份需要该桶快照前缀的写入、读取和上述配置检查权限，无需删除权限。恢复进程使用另行授权的业务桶写入身份。

在 `services/api` 工作目录执行：

```powershell
go run ./cmd/media -operation check
```

首次迁移先停止上传、替换、恢复等写入操作，保留本地原始目录，分别进行预检和迁移；成功后再启用COS配置的API：

```powershell
go run ./cmd/media -operation migrate-local -source-root <原本地图片目录>
go run ./cmd/media -operation migrate-local -source-root <原本地图片目录> -apply
```

迁移仅复制数据库仍引用的面诊、随访照片并逐张核验，不更新照片编号、授权事件或数据库，不删除源文件，可重复执行。源文件缺失或校验不符会失败。

## 故障和孤立文件

存储写入/读取失败、对象丢失或内容损坏返回 `503 MEDIA_UNAVAILABLE` 与 `Retry-After: 5`；响应和存储日志不包含签名链接或密钥。上传写入失败时不发布数据库引用；数据库提交确认丢失时保留已写对象，避免删除可能已提交成功的照片。替换后的旧对象统一由清理任务回收，不依赖请求中的一次删除。

API启动时及每小时扫描存储，仅处理超过24小时且面诊、随访和案例图片表均无引用的 `photo-*` 对象。案例私有副本和历史版本也纳入备份、恢复及引用检查。每个候选对象删除前重新查询数据库。数据库/列表读取失败终止本轮，删除失败计数并保留对象，下轮重新发现和重试。授权撤回不等于删除照片：仍被引用的照片必须保留。开发本地目录中的旧 `.upload-*` / `.probe-*` 普通临时文件也按24小时清理。COS使用简单PUT，不产生分片残留。

```powershell
go run ./cmd/media -operation cleanup
go run ./cmd/media -operation cleanup -apply
```

前者只列出候选统计，后者执行删除。COS清理创建删除标记；历史字节的最终清理由桶生命周期处理。按院方批准的保留期限配置历史版本和不完整快照回收，不能用「删除所有旧对象」策略清理仍有效的照片。监控 `media cleanup failed`、备份进程非零退出、最近成功快照时间；重复失败需告警。

## 加密备份

备份进程独立读取 `deploy/media-backup.env.example` 所列配置。必须设置独立的 `COS_BACKUP_BUCKET`、地域与凭据，`MEDIA_BACKUP_DRIVER=cos`，以及 `MEDIA_BACKUP_KEY`（随机32字节经base64编码）。示例生成密钥，结果仅存入私有密钥文件或密钥管理：

```powershell
$backupKeyBytes = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Fill($backupKeyBytes)
$env:MEDIA_BACKUP_KEY = [Convert]::ToBase64String($backupKeyBytes)
```

密钥丢失将无法恢复快照；轮换后保留旧快照对应的旧密钥。业务照片与清单均使用 AES-256-GCM 加密，独立随机nonce，并绑定快照编号及照片编号，防止对象互换。每张备份写入后都读回、解密并核验SHA-256/长度，最后才写入加密完成清单；没有完成清单的快照不可恢复。快照只保存照片编号、哈希、长度与生成时间，不复制患者姓名、电话、员工会话或授权记录。

```powershell
go run ./cmd/media -operation backup
# 输出 snapshot=snapshot-<32位hex> 和已验证对象数量；退出码必须为0。
```

备份覆盖当前数据库引用的照片；如要匹配数据库全量灾备，在停止所有写入与清理的维护窗口内，生成数据库一致性备份和图片快照，保存二者的对应关系。数据库备份必须包含授权事件、院区权限、照片引用及审计；另配置数据库日志持续备份，确保恢复时能重放备份之后的授权撤回。

Linux部署时先 `go build -o <部署路径>/bin/media ./cmd/media`，创建专用备份账号，把环境文件设为仅该账号可读，按实际路径调整 `deploy/media-backup.service` 和 `.timer` 后安装并启用timer。模板每天北京时间02:00运行，停机错过后会补跑；当前未安装或启用系统定时任务。

Windows 可用任务计划程序调用独立脚本，环境文件限定备份账号访问：

```powershell
pwsh -NoProfile -File scripts/backup-media.ps1 -EnvironmentFile <备份专用环境文件>
```

开发恢复演练可设 `MEDIA_BACKUP_DRIVER=local`、`MEDIA_BACKUP_ROOT=<业务目录外的独立备份目录>`，仍必须配置加密密钥。正式COS主存储禁止本地备份回退。

## 恢复与授权撤回

1. 停止写入、替换和孤立文件清理，选择与当前数据库照片元数据一致的快照。
2. 如数据库也受损，先在隔离环境恢复数据库备份和最新日志，确认最新的授权撤回已重放、员工会话已失效、院区及负责人权限正确；此核验完成前不得开放医护图片接口。单纯恢复旧数据库会丢失之后的撤回记录，图片工具无法替数据库恢复补偿这些事件。
3. 注入该快照的加密密钥及备份读取/业务写入凭据，预检全量对象。快照若缺少当前照片、清单损坏、对象损坏、密钥不符或元数据不匹配，预检失败。
4. 执行恢复，核验后恢复API。恢复按照片编号逐项进行，支持重跑；运行中失败可能已恢复部分文件，须修复原因后再次预检和执行。

```powershell
go run ./cmd/media -operation restore -snapshot snapshot-<32位hex>
go run ./cmd/media -operation restore -snapshot snapshot-<32位hex> -apply
```

恢复只修复数据库当前仍引用的对象，不恢复照片行、授权事件或会话，不复活已替换、已删除引用的照片。患者仍可查看自己的历史照片，医护读取继续要求当前有效的 `photo-care-v2` 授权和当前职责/院区权限。读照片在存储I/O前后各核验一次；图片响应禁止缓存。后台面诊、随访和患者档案照片使用同一组件，当前可见照片每10秒重新鉴权读取，预览授权期限为15秒，读取失败或期限到达时立即清除旧图；页面隐藏或组件卸载立即释放图片及放大预览。已发送到客户端的字节、截图或人为下载无法被服务器追回，持续限制针对后续访问及本应用中的预览。

每次部署至少演练：业务桶私有检查、JPG/PNG上传读取、COS断网与无权限失败、替换后孤立对象回收、加密快照读回、误删恢复、撤回授权后旧照片编号/后台已打开预览无法继续读取、恢复后授权仍为撤回。当前Go测试覆盖故障、清理、快照完整性与恢复；真实MySQL验证覆盖双表引用和恢复后撤回持续有效；浏览器验证覆盖已打开图片和放大预览被清除。真实COS演练待建桶。
