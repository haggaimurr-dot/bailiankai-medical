# 患者身份与资料

患者账号通过 `wx.login` 取得临时 code，由服务端向微信验证，按机构小程序 AppID 与 OpenID 唯一组合取得患者ID。同一微信账号换设备、清缓存或会话过期后重新登录，仍使用同一个患者ID，恢复该患者的预约、照片、方案、治疗和随访。不同微信账号分别管理；不按手机号匹配或合并账号。现有演示患者不自动迁移。

医护人工建档后，可通过限时绑定码让患者本人核对并绑定院内档案。绑定仅接收服务端已验证的微信账号，成功后稳定身份使用人工档案编号；已有业务记录的微信账号返回冲突。流程、会话变化与接口见[后台患者档案与问诊模板](后台患者档案与问诊模板.md#人工档案绑定微信身份)。

## 配置与使用

1. 执行数据库迁移，新增 `00014_patient_identity.sql`。迁移为已有演示患者补齐资料版本和“未授权”状态，不改预约联系人信息。
2. 服务端环境配置 `WECHAT_APP_ID` 和 `WECHAT_APP_SECRET`，AppID 必须与小程序一致；两项必须同时配置。密钥不能放入小程序代码、截图或日志。
3. 小程序 `app/config/api.ts` 的 `PATIENT_LOGIN_MODE` 默认 `wechat`。本地虚构资料联调可显式设为 `demo`，重新构建；演示模式仍遵循过期后确认创建新身份的规则。
4. 首页进入“我的资料”。查看当前账号资料，修改姓名；点击原生手机号授权按钮获取临时 code，服务端验证后更新账号手机号。拒绝授权不改当前状态。
5. 手机号更新需要重新授权；不接受前端直接提交手机号。撤回授权后清除账号手机号及当前授权时间，状态改为“已撤回”。这项操作不影响诊疗照片授权。
6. 资料包含版本号。另一设备修改后，旧版本保存返回冲突；页面刷新最新资料，用户核对后重新操作。
7. 退出仅注销当前设备会话。会话有效期7天，数据库只存令牌摘要；重新登录恢复原患者，不自动建立替代身份。

账号手机号与预约 `contactPhone` 分别保存。预约联系人可以是本人或代办人；表单提供“使用账号手机号填写本次联系人”，需主动点击复制。预约提交后的联系人是该次预约的快照，修改姓名、更新手机号或撤回授权均不会改写历史预约。预约手机号不能用来恢复患者身份。

## API

| 方法与路径 | 用途 |
| --- | --- |
| POST `/api/v1/patient/session` | 服务端验证微信 code，取得稳定患者会话 |
| GET `/api/v1/me` | 查询当前患者资料、账号手机号及授权状态 |
| PUT `/api/v1/me/profile` | 按版本修改姓名 |
| POST `/api/v1/me/phone` | 按版本提交微信手机号授权 code |
| POST `/api/v1/me/phone/revoke` | 按版本撤回手机号授权 |
| POST `/api/v1/me/logout` | 注销当前会话 |

患者资料接口只访问当前会话的患者，不接受指定患者ID。响应不包含 OpenID、AppSecret、微信 session_key 或微信 access_token。临时凭证无效返回400，未登录返回401，资料版本冲突返回409，微信登录未配置返回503。

## 验收与边界

自动测试覆盖：并发首次登录只生成一个患者；换设备和过期恢复；不同患者隔离；资料版本冲突；无效手机号凭证拒绝；授权、撤回后预约联系人保持原值；单设备退出；禁止客户端伪造患者身份或直接改账号手机号；旧会话的迟到响应不覆盖新身份。

真实微信验收还需机构提供服务端凭据、账号具备手机号接口权限、配置小程序隐私保护指引和受控 HTTPS 测试域名。需在微信真机检查授权允许/拒绝、二次授权更新、两个设备恢复以及手机号接口权限/费用。当前项目的 loopback 与 development 限制仍保留，本次代码不代表已上线生产。

官方接口依据：[微信登录](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-login/code2Session.html)、[手机号验证](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-info/phone-number/getPhoneNumber.html)、[稳定 access_token](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/mp-access-token/getStableAccessToken.html)。
