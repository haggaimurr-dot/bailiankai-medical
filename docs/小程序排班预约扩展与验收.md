# 小程序排班与预约扩展

2026-10-07。候补方式经用户确认：患者主动申请空位，仍由工作人员确认。

## 改期

- 从预约详情进入「申请改期」，查询同一医生、同一院区未来 7 天的可用时段。
- 尚未到诊、未记录治疗且原时段未开始的待确认或已确认预约可申请改期。过期待确认不允许改期。
- 确认新时间后，在同一事务中释放原名额、占用新名额、更新预约版本和写入事件。预约编号、联系人及关联诊疗资料保留；成功后重新进入待确认，按当前配置保存新的确认截止时间。
- 新时段已满、停诊、已开始，或版本冲突、重复活跃预约时，整笔换号回滚，原预约保留。
- 请求有独立幂等编号，成功重放返回同一预约的最新状态。同编号更换时段或版本被拒绝。
- 发出请求前在本机保存编号、目标时段、版本及所属患者。结果不明时锁定时段选择；重新进入页面可使用原申请重试，避免重复换号。

## 候补

- 开放、尚未开始、容量大于零且已满的时段显示「登记候补」。正常可用、零容量、停诊或已开始时段不接受候补。
- 候补使用预约联系信息及现有提交恢复流程；状态为 `waiting`，不占用容量。同一患者同一时段的候补、待确认、已确认预约合计最多一条。
- 在详情进入「查询空位并申请转预约」。可申请原时段空位，也可选择同医生、同院区的其他可用时段。
- 申请成功才占号并进入待确认；工作人员确认后才是已确认预约。按申请空位时的事务先后分配容量，候补不提供排队优先权或到院保证，不自动转预约或发送空位通知。
- 开始前可取消候补；时段开始时自动过期。取消和过期候补不释放其他患者的名额。

## 正式预约规则

- 使用实际患者会话读取本人预约，使用持久化员工会话审核，不能用固定演示后台口令代替员工身份。
- 普通提交立即占号、确认不重复占号；拒绝、取消、待确认过期只释放一次。
- 待确认截止时间以服务端保存的配置为准，最晚为时段开始；页面不固定承诺两小时。
- 关闭时段不自动取消已有预约，停止新申请及确认；工作人员仍可拒绝原待确认，患者开始前仍可取消或申请其他时间。
- 到诊或治疗后的预约不能取消或改期；开始后的已确认预约不推定为已治疗或爽约。
- 更改请求内容、过期身份、越权患者、过期预约、旧版本及最后一个名额竞争均由服务端校验。

## 状态时间线

详情读取 `GET /me/appointments/{appointmentId}/timeline` 的真实服务端事件，包括提交、候补、转预约、改期、确认、拒绝、取消、过期、到诊和治疗。按北京时间显示，拒绝原因及改期前后时间保留。事件不返回操作人员 ID、请求编号、请求摘要、手机号或备注。本人鉴权失败返回 404；历史读取失败可独立重试，预约详情仍可查看。事件序号保证同一毫秒内的稳定排序。
