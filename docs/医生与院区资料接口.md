# 医生与院区资料管理

先运行 `services/api` 的 `go run ./cmd/migrate`，应用迁移 18、19，再重启 API。迁移将已有资料视为已发布，回填初始版本及已有预约的医生、院区名称。后台医生与院区维护页面已接入，主管可从“医生资料维护”和“院区资料维护”入口使用。资质及院区展示字段还需应用迁移 28。

接口前缀为 `/api/v1/admin`，全部要求有效主管员工会话；已有院区及医生只允许授权院区内的操作。后台列表包含未发布和停用资料，患者公开列表只返回启用且已发布的资料。院区停用时，其医生和号源也不会在公开列表出现。

| 方法 | 路径（`{kind}` 为 `clinics` 或 `doctors`） | 用途 |
| --- | --- | --- |
| GET | `/{kind}` | 读取授权范围内全部资料，包括停用和草稿 |
| POST | `/{kind}` | 新增草稿，服务端生成 ID，初始版本 1 |
| PUT | `/{kind}/{id}` | 完整替换草稿资料，携带当前 `version` |
| POST | `/{kind}/{id}/status` | `{"version":1,"active":false}` 停用；true 启用 |
| POST | `/{kind}/{id}/publish` | `{"version":1}` 发布当前草稿 |
| GET | `/{kind}/{id}/history` | 读取历次草稿、发布、启停及账号关联快照 |
| POST | `/doctors/{id}/employee` | 关联员工账号，携带 `employeeId`、医生 `version` 和 `employeeVersion` |

新增院区请求：

```json
{"name":"演示院区","address":"演示地址","phone":"021-00000000"}
```

新增医生请求：

```json
{
  "clinicId":"clinic-demo",
  "name":"演示医生",
  "title":"演示职称",
  "summary":"演示简介",
  "focus":["面诊咨询"],
  "initials":"医",
  "avatarUrl":"https://example.com/avatar.jpg",
  "serviceIntroduction":"该医生的专属服务介绍，可含换行。"
}
```

修改时在以上请求中增加 `version`。头像采用外部 HTTPS 图片地址，空字符串清空；本次没有头像文件上传接口。服务介绍最长 5000 字，可留空；小程序无头像时显示缩写，无专属介绍时显示通用流程。真机展示图片须符合微信图片域名配置。

每次修改、发布或启停都会递增版本，并在同一事务追加包含操作者、时间、动作、资料内容的历史记录。过期版本返回 409；字段缺失、未知字段、null、超长值或非 HTTPS 头像返回 400；授权范围外的目标返回 404；非主管返回 403。草稿修改后，患者继续查看上次发布的快照；启用不会自动发布草稿。停用资料不能发布，医生发布还要求所属院区已启用且已发布。

新增医生会同时建立同 ID 的医护人员身份。可以通过已有员工新增接口，使用医生 ID 作为 `staffId` 创建 doctor 角色账号；显式关联接口则要求账号处于启用状态、为 doctor 角色且获授权该医生院区。每位医生最多一个员工账号，关联会撤销该账号已有会话并记录双方历史。已有其他医护身份的账号不能直接改绑，避免转移历史诊疗访问权；医生所属院区也不允许原地更换。

新建院区会在同一事务授予创建主管该院区权限，并追加账号授权事件；当前主管重新获取员工会话资料即可看到新授权。其他主管仍需通过原有院区授权接口配置。

停用只关闭公开展示与新预约入口，不删除医生、院区、号源、预约、方案、治疗或随访资料，也不取消已存在的预约。预约保存提交时已发布的医生、院区名称，后续更名不会覆盖旧预约名称。重复提交原请求键仍可恢复已有预约。医生资料启停独立于员工账号停用及医护离岗交接；历史诊疗和未完成随访沿用已有权限与交接流程。

验证：`pnpm check`、`go vet ./...`；设置专用 `_test` 数据库后运行 `go test ./internal/store -run 'TestDirectory|TestPrivacyConsentHistoryAndClinicIsolation' -count=1`。覆盖草稿发布隔离、版本冲突、头像/服务返回、停用拦截、历史名称、跨院区拒绝、新增资料、账号关联及会话撤销。

## 后台维护页面验收

- `/doctors`：主管读取授权范围内草稿、已发布及停用医生，按名称、院区、状态筛选；其他角色保留公开医生查看页。
- `/clinics`：主管维护院区，入口权限由员工会话 capabilities 返回。新增院区成功后刷新主管会话以取得新增院区授权。
- 新增和编辑保存完整草稿，医生所属院区编辑时不可变更。启停和发布使用最新版本号；遇到 409 保留输入、刷新列表并禁用旧版本保存，需重新打开资料。
- 发布预览对照当前草稿和上次发布快照，兼容 published、migrated、seeded 历史格式。编辑中可预览未保存内容，但须先保存再从列表发布。停用资料、所属院区未启用或未发布的医生禁止发布。
- 医生与院区支持最多 20 项资质，每项包含名称、编号、颁发机构及 HTTPS 图片附件地址。支持添加、移除、保存、放大预览、历史快照展示。沿用现有接口的公开图片地址，无本地文件上传接口。
- 院区可维护品牌、标语、介绍、标志、营业时间、交通、到院指引及 GCJ-02 坐标；经纬度同时填写或同时留空。
- 历史页显示版本、动作、操作者、北京时间及当时资料。账号关联页仅列出启用的 doctor 角色、获授权该院区、未绑定人员的账号；已关联账号显示绑定状态。关联请求包含医生及员工双方版本，成功后重新加载医生版本。
