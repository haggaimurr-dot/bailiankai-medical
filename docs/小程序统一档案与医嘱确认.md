# 小程序统一档案与医嘱确认

档案入口为 `pages/records/index`，方案详情为 `pages/care-plan/index`。

## 时间轴

患者自己的问诊、复诊、方案发布、实际治疗、随访任务、随访提交、医护回评、预约统一按事件时间倒序展示。独立问诊无需关联预约。复诊展示前次问诊关联、阶段进度、建议复诊时间。随访任务以应填写时间展示，提交和回评各自以实际时间展示；时间均为北京时间。

问诊与复诊使用相同的记录卡片，展示主诉、病史与既往情况、评估结论及医嘱；`TimelineEvent.history` 返回病史，其他类型事件为空字符串。切换患者身份后，不继续显示或追加原账号记录。

服务端统一分页，每页默认20条，以时间、类型、记录编号稳定排序。只包含已发布方案，不返回草稿。

- `GET /api/v1/me/records?page=1&pageSize=20`：返回 `data` 和 `meta`。
- `GET /api/v1/me/records/{kind}/{resourceId}/read`：返回指定问诊/复诊/方案的医嘱和阅读状态。
- `POST /api/v1/me/records/{kind}/{resourceId}/read`：提交 `{ "adviceVersion": "<64位内容摘要>" }`。

所有接口使用当前患者会话，禁止通过参数选择其他患者；其他患者的记录返回404。响应包含 `Cache-Control: no-store`。

## 医嘱确认

在时间轴或方案详情点击“我已阅读医嘱”，明确确认后才保存，打开页面不会自动确认。保存具体患者、记录类型、记录编号、医嘱内容摘要和服务端时间。重复请求保留首次确认时间；网络失败可重试。无医嘱内容不显示确认按钮。内容版本不一致返回409，刷新后确认；新版方案即使医嘱文字相同，也需单独确认。

阅读确认只表示患者阅读了医嘱，不作为知情同意或治疗授权。

方案详情确认失败保留方案内容和确认按钮，可以直接重试；内容版本冲突时提示下拉刷新。确认成功直接使用服务端回执更新当前版本的阅读时间，不依赖再次加载方案。登录失效时清除页面上的方案内容。

## 发布与验证

部署前运行现有迁移命令，执行 `00027_advice_receipts.sql` 建立阅读回执表。正常生产迁移不删除现有记录。

- `pnpm --filter @bailiankai/miniprogram test:records`：页面分页、确认、取消、失败重试、登录失效、旧请求处理、方案详情与跳转。
- 配置专用 `_test` MySQL 后，在 `services/api` 运行 `go test ./internal/store -run TestPatientTimelineAndAdviceReceipts -count=1`：验证实际SQL、独立问诊与复诊关联、统一分页、患者隔离、并发重复确认、版本隔离及HTTP接口。
- `pnpm check`：契约、类型、小程序回归测试及构建。
