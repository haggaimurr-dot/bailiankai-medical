# 面诊照片拍摄与验收

## 当前实现与验证边界

小程序 `pages/care-photos/index` 提供正面、左侧、右侧的标准化拍摄说明，分别提供“拍摄”和“相册”入口。选择器优先调用微信 `chooseMedia`，不可用时使用 `chooseImage`，每次只接收一张原始图片；来源限定为当前按钮对应的 `camera` 或 `album`。

选取后先在本机检查并展示预览，不立即上传。检查包括图片尺寸以及可执行时的清晰度、光线抽样；设备支持时调用微信静态照片人脸检查，提示无人脸、多张人脸、取景过小或靠近边缘等情况。角度由患者对照当前角度的拍摄说明核对。需要分别确认“清晰度”和“角度”才能保存。自动检查发现阻断项时禁止保存；自动清晰度检查不可用时显示需要人工确认，不能把“未检查”显示为“通过”。图片内容和抽样像素不发送到额外服务。

清晰度抽样是拍摄辅助规则，不能保证识别人像失焦、局部模糊或所有曝光问题。当前未通过人脸关键点模型判定左右姿态，也不提供医学判断。真实角度的验收应查看所选测试照片，不能用几何测试图证明人像角度正确。

质量规则当前如下，均为拍摄提示或最低输入要求，并非临床质量标准：

| 检查 | 当前规则 | 结果 |
| --- | --- | --- |
| 尺寸 | 无有效尺寸或短边小于 320 像素 | 阻断，重选 |
| 尺寸 | 短边 320–639 像素 | 提醒建议短边至少 640 像素 |
| 清晰度 | 图片最长边抽样到最多 512 像素；人脸区域或画面中央计算拉普拉斯方差及对比度；方差低于 80 或对比度低于 12 | 可能模糊/纹理不足提醒，人工放大核对 |
| 光线 | 平均亮度低于 45、暗像素占比超过 35%，或平均亮度高于 220、亮像素占比超过 35% | 偏暗/过曝提醒，建议重拍 |
| 角度 | 单人脸及取景辅助检查；未校准可靠的姿态阈值及镜像左右 | 始终需要按角度说明人工确认 |
| 能力不足 | 图片读取失败则阻断；canvas 或静态照片人脸检查不支持/超时 | 已完成检查保留，其余明确显示人工核对 |

照片授权仍为独立的诊疗及随访用途授权。正面、左侧、右侧每个角度只保留当前一张；确认新照片后才替换原图，取消选择或放弃检查预览不会替换。已治疗的预约仅允许查看面诊照片。撤回授权后医护端不能继续读取，患者仍能查看自己的已保存照片。

本文区分三类验收：

| 验收层级 | 可以证明的内容 | 不覆盖的内容 |
| --- | --- | --- |
| 自动化回归与 `smoke:care --photos-only` | 本地质量规则、检查确认门槛、真实 API 上传下载、替换与授权撤回 | 使用选择器替身，不证明原生相册或相机工作 |
| `smoke-photo-picker.mjs` 交互验收 | 从实际渲染节点读取来源与角度，调用真实页面处理函数；核对原生选择器、检查预览及上传下载 | 不证明按钮点击绑定或 iOS/Android 真机；必须由操作者实际完成系统窗口操作并确认观察 |
| iOS/Android 真机清单 | 手机相机/图库、设备权限与隐私指引、图片方向和实际拍摄可用性 | 需受控测试服务和设备，不能从模拟器结果推断通过 |

未实际运行并核对的平台应记录为“待验收”，不能只因脚本已提供就记为“通过”。当前尚未取得本轮真实相机、相册或 iOS/Android 真机的通过记录；原生联调中曾遇到开发者工具 `Page.*` 自动化通道超时，属于未完成验收，不可据此判断相机/图库本身不支持。交互脚本已改用能工作的 `App.callFunction` 读取实际页面数据与执行处理函数，并通过微信原生 selector query 核对按钮渲染信息。

## 拍摄规范与角度说明

在自然、均匀的光线下拍摄，避免逆光、强阴影和过曝。关闭美颜、滤镜，保持同一背景、距离及机位；头发收起，露出面部轮廓，避免口罩、眼镜或其他物体遮挡。镜头与眼睛大致等高，保持头部端正和自然表情，画面应完整包含额头至下巴。

先阅读所选角度的示意和说明，再打开相机或相册。左、右以被拍摄者自身方向判断，不能根据镜像预览左右互换。保存前放大检查眼睛及面部细节、轮廓和角度；明显模糊、遮挡或角度不符时重新拍摄或重新选择。使用同一角度的拍摄要求对比后续照片。

## 开发者工具交互验收

前提：Node 22+、本地演示 API 与数据库可用、小程序已构建、微信开发者工具已开启服务端口。只使用测试图片、几何图片或得到明确同意的演示资料。关闭其他小程序自动化测试，使用新启动的工具会话，确保没有遗留的选择器、图像检查或上传替身。

在仓库根目录执行，微信 CLI 路径按本机安装位置调整：

```powershell
pnpm --filter @bailiankai/miniprogram build
& 'D:\app\wechatdev\微信web开发者工具\cli.bat' auto --project 'D:\proj\百莲凯医疗美容\apps\miniprogram' --auto-port 9420 --trust-project
node apps/miniprogram/scripts/smoke-photo-picker.mjs --source=album --angle=front --expect=success
node apps/miniprogram/scripts/smoke-photo-picker.mjs --source=camera --angle=front --expect=success
```

脚本不使用 `mockWxMethod`，不替换 `chooseMedia`、`chooseImage`、图像读取、canvas 或上传。它创建隔离的演示身份及待确认预约，准备测试身份的隐私同意，再打开照片页；照片用途授权对话框由操作者在工具中实际确认。由于当前开发者工具的 `Page.*`/元素点击自动化通道可能超时，脚本用微信 `createSelectorQuery` 读取对应来源按钮的真实 dataset 及尺寸，再调用当前页面真实 `choose` 处理函数；它验证实际选择器调用及来源传递，但不证明按钮点击事件绑定。完整点击入口仍需手动点击验收。

1. 在弹出的系统窗口中实际选择或拍摄测试照片。系统窗口通常不能通过微信页面自动化操控，脚本等待操作者完成。
2. 成功场景先停留在检查预览，不急于保存。脚本核对服务端仍无照片后，终端会提示可以继续。
3. 对照页面逐项核对，分别勾选清晰度和角度，再按“确认保存”。脚本核对真实上传、页面预览和患者鉴权读取。
4. 只有确实看到并操作了原生相册/相机窗口，才在终端输入 `NATIVE`。未看到、相机不可用、自动化超时或没有完成检查时，验收不会记录为通过。

按角度补齐相册与相机两组记录：

```powershell
node apps/miniprogram/scripts/smoke-photo-picker.mjs --source=album --angle=left --expect=success
node apps/miniprogram/scripts/smoke-photo-picker.mjs --source=album --angle=right --expect=success
node apps/miniprogram/scripts/smoke-photo-picker.mjs --source=camera --angle=left --expect=success
node apps/miniprogram/scripts/smoke-photo-picker.mjs --source=camera --angle=right --expect=success
node apps/miniprogram/scripts/smoke-photo-picker.mjs --source=album --angle=front --expect=cancel
node apps/miniprogram/scripts/smoke-photo-picker.mjs --source=camera --angle=front --expect=cancel
node apps/miniprogram/scripts/smoke-photo-picker.mjs --source=album --angle=front --expect=rejected
```

`cancel` 场景在系统窗口取消，应没有检查草稿和上传；`rejected` 使用短边小于 320 像素的测试图片，要求存在质量阻断项并且没有上传。模糊或曝光问题通常产生提醒，不属于该阻断场景，应另行核对提醒和人工确认门槛。两类场景也需要确认实际原生窗口。可用 `--timeout=180` 调整等待上限（30–900 秒），`--evidence=tmp/自定义记录.json` 指定记录位置。缺少交互终端不能完成观察确认。

默认 JSON 记录写到运行目录的 `tmp/photo-picker-<来源>-<角度>-<场景>.json`，包括运行时间、微信工具版本、来源、角度、尺寸、检查状态、上传/读取结果、操作者原生窗口确认及清理状态。不会写入患者令牌、所选文件路径、图片字节或原生异常载荷。相同组合再次运行会更新对应记录；需保留历史时指定不同文件名。

结束后撤回本次演示预约照片授权、取消仍有效的测试预约并恢复原三个业务缓存项。演示照片引用和审计保留，未删除数据库记录或其他资料。若记录的 `cleanup` 为 `requires_attention`，按记录所列事项处理后再运行；断开工具、强制关闭 Node 或退出系统可能需要手动恢复测试缓存。脚本失败不等于原生能力一定不支持，应按失败阶段确认工具权限、摄像头、基础库及自动化连接。

原有替身流程回归：

```powershell
pnpm --filter @bailiankai/miniprogram smoke:care --photos-only
```

该回归使用 900 × 1200 的清晰几何 PNG，实际执行图像检查；验证未确认、只确认清晰度时不会上传，双项确认后完成正面/左侧/右侧上传与替换，再核对撤回后医护访问被拒绝、患者查看仍有效。它使用选择器和确认框替身，应与上面的原生选择器结果分别记录。

## iOS / Android 真机清单

目前 API 地址为电脑 loopback，手机不能直接访问。真机前先准备受控 HTTPS 测试服务、微信 request/upload/download 合法域名、微信登录凭据及必要隐私指引，再构建测试版本。在 iOS 与 Android 各至少运行一轮：

| 场景 | 验收标准 |
| --- | --- |
| 相机拍摄三角度 | 按钮直接进入相机；真实前/后置拍摄可返回检查预览；来源与保存角度正确 |
| 相册选择三角度 | 原生图库可选取；仅一张图片进入检查；错误角度可以放弃重选 |
| 取消与拒绝权限 | 取消不上传、不替换；拒绝相机/图库权限后有可理解提示，返回页面可恢复操作 |
| 平台隐私授权 | 首次涉及受保护 API 时的微信隐私指引及授权流程可完成；拒绝后不上传 |
| 图像方向及格式 | 竖拍、横拍、前置镜像、带 EXIF 方向的照片正确显示；不支持的格式明确提示重选 |
| 清晰度与角度 | 低分辨率/模糊测试图被提示或阻断；缺少任一确认不能保存；左右方向与被拍摄者一致 |
| 中断及旧图保护 | 后台切换、断网、切页、上传失败可重试；取消替换仍能查看原已保存照片 |
| 授权及身份 | 未授权不能选取上传；撤回后医护不能查看；切换身份不保存到其他账号 |
| 查看模式 | 已治疗预约不能补传或替换面诊照片；历史照片正常读取 |

记录设备型号、系统版本、微信版本、基础库版本、所测来源/角度、用例结果与失败原因。需要截图时只截测试资料，单独保存；不要把真实患者照片或令牌放入验收记录。
