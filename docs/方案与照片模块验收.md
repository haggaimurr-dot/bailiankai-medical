# 方案与照片模块

后台 `/care` 的预约列表使用服务端 `q` 搜索（姓名、手机号、预约编号），每页 20 条，通过 `meta.total` 翻页，不再只读取前 100 条。可切换已确认和已治疗预约；翻页和搜索保留当前打开的方案。患者档案和随访传入的 `appointmentId` 可直接打开跨页预约，仍由服务端校验访问范围。

历史版本显示摘要、所有阶段正文、医嘱、发布人、发布时间与修订说明。全文对照支持任意两个已发布版本，以及历史版本与当前编辑内容。阶段按位置比较，新增、删除和修改字段高亮，可选择只看差异；相同内容显示无差异。历史版本保持不可变。

个人模板存储于服务端，支持保存当前完整方案、选择应用及删除。名称最多 80 字，内容沿用草稿校验。应用前确认覆盖，只修改编辑区，仍须保存草稿、填写发布说明并发布。模板仅当前员工可见；主管、医生、护理及兼容医护账号可管理本人模板，客服和运营无权访问。护理方案编辑仍只读。模板中不应填写患者身份资料。

发布按钮在存在未保存修改时禁用，确保发布的内容与已保存草稿一致。切换预约前提示丢弃未保存编辑。已治疗预约只读。

部署前执行数据库迁移 `00041_care_plan_templates.sql`，创建模板表。新增接口：

- `GET /api/v1/admin/care-plan-templates`
- `POST /api/v1/admin/care-plan-templates`，请求 `{name, content}`
- `DELETE /api/v1/admin/care-plan-templates/{templateId}`

接口从员工会话获取模板归属，不接受客户端指定 owner；越权删除返回 404，响应禁止缓存。

回归：`pnpm exec playwright test tests/care.spec.ts`；后端 `go test ./internal/httpapi -run TestCareTemplateOwnershipAndValidation`；持久化隔离验证 `go test ./internal/store -run TestCareTemplatesPersistAndIsolateOwners`，后者需 `TEST_DB_DSN` 指向专用 `_test` 数据库。
