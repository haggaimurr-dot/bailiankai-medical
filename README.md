## 本地启动（Windows / PowerShell 7）

前置工具：Node.js 22.12+、pnpm 11.19.0、Go（支持自动下载 1.27.1 工具链）、Git。微信端使用微信开发者工具。

在本目录运行：

```powershell
pnpm install --frozen-lockfile
pnpm contracts:generate
pnpm tokens:sync
pnpm build:miniprogram
pwsh -File scripts/setup-local.ps1
pwsh -File scripts/start-dev.ps1
```

首次 setup 会从 MySQL 官方下载 8.4.11 Windows ZIP（约 268 MB），校验包摘要并解压到 `.local`。它仅在 `127.0.0.1:3307` 启动独立数据库，不注册 Windows 服务。为兼容中文目录，脚本在 `%LOCALAPPDATA%/bailiankai-runtime` 建立英文路径的目录联接，指向本项目 `.local`；数据仍保存在项目内。数据库、日志和随机生成的本地凭据都在 Git 忽略目录内。请保留 `.local/mysql/data`，重新运行 setup 不清空数据库。

首次启动会创建本地主管账号。账号与初始随机密码保存在 `.local/employee-credentials.txt`；登录后在“员工账号”开通个人账号并关联随访人员。此文件只用于首次引导，密码请妥善保存。员工会话 12 小时有效；停用账号、重置密码和关联人员离岗会使访问失效。

- 预约管理：[打开后台](http://127.0.0.1:5173/appointments)
- 方案与照片：[打开医护工作台](http://127.0.0.1:5173/care)
- 治疗与随访：[打开随访工作台](http://127.0.0.1:5173/followups)
- 排班工作台：[管理号源](http://127.0.0.1:5173/schedule)
- 员工账号：[开通和管理账号](http://127.0.0.1:5173/employees)
- 患者档案与导出：[选择患者、创建导出任务及查看审计](http://127.0.0.1:5173/patients)
- API 就绪检查：<http://127.0.0.1:8080/readyz>
- 停止后台和 API：`pwsh -File scripts/stop-dev.ps1`
- 一并关闭本项目数据库：`pwsh -File scripts/stop-dev.ps1 -Database`

如果已有进程占用 3307、8080 或 5173，先检查该进程用途；启动脚本不会主动终止其他项目。

### 小程序

首页“我的资料”支持登录、姓名修改、手机号授权/更新/撤回及退出当前设备。微信模式默认启用，服务端需配置 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`；同一微信账号在不同设备或过期后登录恢复同一患者。账号手机号与每次预约联系人手机号独立管理。继续使用虚构患者验收时，将 `apps/miniprogram/app/config/api.ts` 中 `PATIENT_LOGIN_MODE` 显式设为 `demo` 并构建。配置与验收详见 [患者身份与资料](docs/患者身份与资料.md)。

微信开发者工具导入 `apps/miniprogram`，项目已配置机构 AppID。先执行 `pnpm build:miniprogram`，再按小程序目录的 README 构建 npm。修改 TypeScript 源码后重新执行构建，或保持 `pnpm dev:miniprogram` 运行来自动编译。项目使用本地 TypeScript 编译步骤，避免依赖开发者工具插件的行为差异。

启动本地 Go 服务，在开发者工具的本地设置中临时关闭开发域名校验，便可读取 `127.0.0.1:8080`。此设置只适用于开发调试。真机不能用手机自身的 `127.0.0.1` 访问电脑；后续通过符合平台要求的测试域名接入，并单独做真机验证。

### 验证

```powershell
pnpm check
pwsh -File scripts/check.ps1
```

`check.ps1` 运行契约一致性检查、双端类型检查和构建、患者会话竞态回归、Go 测试/静态检查与浏览器集成测试。浏览器测试需要已启动的本地服务及 Chrome；测试会建立独立演示患者与预约，结束时取消剩余活跃预约并保留操作记录。排班测试会临时修改演示号源，再恢复其容量与状态。MySQL 集成测试只允许使用名称以 `_test` 结尾的独立库。

微信模拟器另有 `apps/miniprogram/scripts/smoke.mjs`，验证原生页面实际读取 API 和后台修改后的刷新；`smoke-booking.mjs` 验证提交、确认、取消、我的预约及成功响应丢失后的原请求恢复。运行方式见小程序 README，依赖本机微信开发者工具的自动化服务。预约脚本使用独立演示身份，结束后恢复原本机身份与草稿，保留测试操作记录并释放测试占号。

M2 验收执行 `pnpm --filter @bailiankai/miniprogram smoke:care --photos-only` 和 `smoke:care --plan-only`（导航不稳定时分场景重开工具）。M3 原生随访验收执行 `pnpm --filter @bailiankai/miniprogram smoke:followup`。两者只使用独立演示身份和合成图片，会恢复原缓存并保留演示审计；治疗记录验收产生的预约在完成治疗时已释放占号。

## 已实现的流程

1. 小程序选择医生和未来时段，填写联系人与手机号后提交，立即占用一个名额。
2. 后台预约管理查看待确认队列，确认或填写原因后拒绝。
3. 患者在“我的预约”查看结果；就诊开始前可取消待确认或已确认预约。
4. 待确认最多保留 2 小时且不晚于就诊开始，到期释放名额。取消、拒绝同样释放名额。
5. 重复提交使用同一请求键，只建立一条预约；网络结果不明时按原请求找回。
6. 后台支持单个创建、按日期范围与星期批量生成、容量与开放状态修改，以及所选时段停诊；批量操作遇到冲突整批回滚，停诊保留已有预约并记录原因。详见 [排班管理规则与验收](docs/排班管理规则与验收.md)。
7. 患者从本人预约详情进入照片页，可按正面、左侧、右侧上传和替换照片。上传前需记录诊疗用途授权；撤回后医护端停止查看照片。照片是选填项，不阻断预约。
8. 后台“方案与照片”工作台按已确认预约查看患者授权照片、编辑带版本检查的方案草稿并发布；患者端只显示已发布版本。

9. 后台“治疗与随访”按已确认预约选择本次依据的已发布方案，录入实际治疗时间、摘要和随访天数；在同一事务生成任务并将预约标为“已治疗”、释放预约占号。每条预约只记录一次实际治疗，相同内容重试不重复建任务。
10. 患者从“我的预约”或预约详情查看随访任务，填写当前感受、症状与选填照片。照片按任务保存，提交后冻结；反馈明显/严重不适或主动请求关注会进入异常队列。
11. 医护提交普通回评；异常任务必须填写给患者的回评及实际处理记录才能完成处理。患者可刷新查看结果。支持分页、逾期未提交筛选、版本冲突保护和操作审计。
12. 诊疗及随访照片使用 v2 授权文本；旧 v1 不自动扩展用途，需患者重新同意。撤回后医护不能重新取得面诊或随访照片，患者自身仍可查看。详见 [M3 随访规则与验收](docs/M3随访规则与验收.md)。

时段为演示用 30 分钟、默认容量 3，容量编辑范围 0–100，不能低于已占用名额。关闭时段仅阻止新预约，不自动取消已有预约。详细约定见 [M1 预约规则与验收](docs/M1预约规则与验收.md)。

`PENDING_CONFIRMATION_MINUTES` 默认为 120，修改后重启 API，只影响新建预约。已有预约保留原确认截止时间。自动过期任务每 15 秒运行，重启后补处理，查询与业务操作也会校正过期状态。

## 统一患者档案

后台新增“患者档案”独立目录，支持按姓名或患者编号搜索、分页；预约详情也可跳转该患者档案。患者身份以患者 ID 为准，不按联系姓名或手机号合并。

档案按患者汇总所有有权查看的预约、已发布方案历史、治疗与修订记录、随访及已授权的面诊/随访照片。问诊记录独立于预约，支持记录主诉、病史/过敏史、评估和建议，保存时记录操作员工与时间，不提供覆盖历史记录的编辑入口。

管理员可查看全部患者；医护仅能查看本人接诊或获分配随访的患者及对应预约，问诊记录仅记录人本人和管理员可见。照片沿用现有患者授权、私有媒体鉴权和访问审计，不提供公开图片地址。升级需执行数据库迁移（新增 `00015_patient_records.sql`）。

## AI 辅助评估

评估入口、任务列表/详情、结果及医生复核页面已连接共享后端。支持独立授权与照片、持久质检/分析队列、冻结版本、有限重试、分配、复核更正和审计。患者只读本人及医生发布结果；主管可分配，当前在岗医生可复核。默认未配置质检/模型，明确显示不可用；使用受控网关需补齐环境变量并重启。见[AI服务端与验收](docs/AI辅助评估服务端与验收.md)。

## 开发环境边界

API 必须显式设置 `APP_ENV=development` 和 `ENABLE_DEMO=true`，后台使用员工账号登录。患者会话只能访问本人的记录，不能用作员工令牌。会话有效期 7 天，数据库只存令牌摘要。微信患者重新登录恢复原身份；演示模式过期后需确认创建新身份，旧预约不会自动转移。现有演示身份与微信身份不自动合并。

服务目前仅允许 loopback 监听，不可直接部署提供真实服务。M2 照片保存在项目 `.local/private-media` 私有本地目录，须通过鉴权接口读取；COS适配及订阅提醒已有代码，真实桶/凭据、微信平台投递、真机与生产部署仍待外部配置和验收。请勿使用真实患者资料。

完整验证记录见 [开发进度](docs/开发进度.md)。
